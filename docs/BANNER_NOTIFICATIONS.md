# 차량 상태 배너·휴대폰 알림

2026-11-10 구현. 휴대폰 모듈은 이 작업 폴더의 기존 `phone/`을 사용한다. 차량 상태를 받는 `CareExchange.receive` 및 폰 기록 변경에서 공통 `BannerNotifications`로 연결한다. 실제 Bluetooth 전파 검증은 [일괄 목록](BLUETOOTH_VALIDATION_CHECKLIST.md)에서 별도로 관리한다.

## 디자인과 상태

- `design/banner` 원본 133개를 보존했다. 1080×340 배너 66쌍(밝음/어두움)을 `phone/src/main/res/drawable-nodpi/banner_*.png`로 복사한다. `tools/prepare-banner-assets.py`가 대응표·SHA-256을 `design/banner/catalog.json`에 생성한다.
- 6종: 주유 완료, 세차 완료, 엔진오일 교체 완료, 모두 완료, 주유 필요, 세차 필요.
- 정비15분류 ×4조합: 단독, 주유 동반, 세차 동반, 주유·세차 동반. 엔진/오일압력/과열/저전압배터리/ABS/EPB/MDPS/TPMS/ESC/에어백/전조등/배기/구동계/수소/액량.
- 확인 질문은 원본 합성 참고 이미지의 캐릭터·배경·버튼 스타일을 Compose로 구성했다. 실제 문구는 사용자 합의대로 ‘세차한 것 같아!’ / ‘세차 안 했어요’이다.
- 주유+세차만, 미분류 경고, 워셔액은 제공된 전용 그림이 없어 네이티브 문구·캐릭터를 사용한다. EV는 주유→충전 문구로 바꾸고 ‘주유’가 박힌 그림을 사용하지 않는다. 다른 부품 그림을 임의로 대신 선택하지 않는다.

## 세차 판단과 취소

`WashLocationEvidence.DedicatedSelfWash` 또는 `SeparatedWashArea`가 검증되고 기존 시설별 체류·패턴·이탈 조건을 모두 충족하면 `ClearFacilityPattern` → ‘세차 완료!’. 그 외 적격 방문은 `EstimatedVisit` → 우선 기록·100% 기준 적용 후 질문. 전용 셀프라도 시설 입장/짧은 체류/P단만으로 완료하지 않는다. 정차식에는 N단을 강제하지 않는다.

완료 문구도 시설·행동 기반 추정이며 SDK의 실제 물세차 완료 신호를 뜻하지 않는다. 확인 질문의 알림 액션과 앱 내역 상세에서 ‘세차 안 했어요’를 누르면 해당 차량·visitId만 취소하고 점수를 복원한다. 첫 세차 기록이었다면 null로 복원한다. 알림 스와이프·앱 배너 닫기는 반영을 유지한다. 취소 ID를 보존해 중복·재전송으로 부활하지 않는다. 취소 기간은 반영 시점부터7일이다.

## 알림 내역과 전달

`NotificationHistory`는 SQLite에 이벤트를 먼저 저장하고 시스템 게시 결과를 별도로 저장한다. 권한 거부·채널 차단·앱 설정 OFF·게시 오류를 성공으로 기록하지 않는다. 읽음·취소·원래 이벤트 시각·차량·추정 방문 ID·시험 출처를 보존한다. 인덱스와50개 단위 페이지를 사용하며 DB/이미지 작업은 IO에서 수행한다. 무한 폴링이나 새 의존성은 없다.

휴대폰 홈 ‘알림 내역’, 알림 탭, 알림의 내역 버튼에서 실제 저장 목록/해당 상세를 연다. 목록은 제공 배너 이미지의 테마별 원본을 표시하고 큰 글씨에서는 네이티브 텍스트로 전환한다. 질문 상세에도 취소 버튼이 있다.

같은 상태 지속·같은 이벤트 재수신은 한 번만 게시한다. 정비 경고는 분류별로 따로 추적해 여러 경고를 놓치지 않고, 같은 분류가 바뀌면 이전 시스템 알림을 정리한다. 최신 유효한 명시적 정상으로 해제된 뒤 재발하면 새 이벤트다. 미수신·단절·오래된 값·시동 자체점검 의미가 미검증인 ON/점멸을 부품 고장으로 단정하지 않는다. 정상 수신은 정비 완료가 아니다.

연료·배터리·일반 경고도 메시지 발행 시각과 원본 수신 시각을 분리한다. 이 버전이 보내는 원본 시각이 null이거나60초를 지났으면 새 메시지에 포함돼도 최신 경고로 쓰지 않는다. 기존 원본 시각 필드가 없는 이전 버전 프레임은 메시지 관측 시각 기준의 호환 경로를 유지한다.

당일 명시적 수동 관리기록 추가에 완료 배너를 연결했다. 최초 과거 기록 가져오기·메모 수정·오일압력/액량 정상 수신으로 교체 완료를 만들지 않는다. 제공된 경고 디자인이 존재하더라도 실제 경고 타입의 공식 판정 규칙·SDK 수신이 미검증이면 활성화하지 않는다.

Android가 접힌 알림의 제목·본문·아이콘과 시스템 장식을 관리하므로 제공 이미지는 펼친 BigPicture 알림 및 앱 내역에서 사용한다. HIGH 채널 게시와 실제 heads-up 노출은 구별한다. [Android 알림 스타일](https://developer.android.com/develop/ui/views/notifications/expanded), [커스텀 알림 제한](https://developer.android.com/develop/ui/views/notifications/custom-notification), [알림 권한](https://developer.android.com/develop/ui/views/notifications/notification-permission).

### 2026-11-14 상단 배너의 작은 아이콘 강조색 수정

- 사용자 확인: 오른쪽 캐릭터가 아니라 **왼쪽 작은 앱 아이콘의 원형 배경**이 주유·경고에도 기본 파란색으로 남았다. `setLargeIcon`은 이미 이벤트별 캐릭터를 선택했지만, `Notification.Builder.setColor`가 없어 작은 아이콘은 시스템 기본 강조색을 사용했다.
- 알림 이벤트의 mood별 강조색을 지정했다. NORMAL 파랑, FUEL 노랑, WASH 분홍, OIL 보라, ANGRY 빨강, EXHAUSTED 회색이다. 작은 자동차 모양과 상태별 큰 캐릭터·제목·본문은 유지한다. 알림 생성 시 이벤트 상태를 사용하므로 앱 런처 아이콘이 NORMAL이어도 주유 알림은 FUEL 색을 갖는다. 시스템이 가독성 대비를 보정하므로 실제 주유 아이콘 배경은 진한 금색 계열로 표시될 수 있다.
- 휴대폰 AVD `Vemoring_Phone_API_34`만 실행하고 격리된 verification 패키지로 검사했다. 다른 앱(설정)이 화면에 열린 상태에서 6종의 실제 상단 배너를 게시하여 Notification.color, 큰 캐릭터 리소스, 문구를 확인했다. 수정 전 APK는 FUEL 강조색이 0으로 회귀 검사 실패, 수정 후 6종 검사는 `OK (1 test)`다. 주유 금색/경고 보라/복합 빨강·회색의 실제 System UI 스크린샷도 확인했다.
- 두 앱 debug APK와 폰 verification/계측 APK 빌드, 폰 verification lint 통과. 알림 소리·채널 중요도·경고 판정·Bluetooth 자동 복구 코드는 변경하지 않았다. 자료: `build/diagnostics/notification-icon/`의 `before-fix-test.txt`, `after-fix-test.txt`, `after-fuel.png`, `after-oil.png`, `after-angry.png`, `after-exhausted.png`, `build.txt`. 초기 수정 전 PNG는 설정 앱 첫 시작 화면만 찍혀 비교 증거로 쓰지 않는다. 삼성 One UI 실기기 재검사는 이번 실행에 포함되지 않는다.

## 검증 범위

격리된 `com.example.vemoring.phone.verification` 앱에만 시뮬레이션을 허용하고 모든 시험 이벤트에 ‘시뮬레이션’을 표시한다. 실제 SDK/무선 수신이 성공한 것으로 취급하지 않는다. 결과·로그·화면은 `build/diagnostics/banner/`에 보관한다.

- 전체66쌍 리소스·상태 매핑과 실제132개 Android 알림 게시/중복 억제를 검증한다.
- 애매한 세차 질문→실제 알림 취소 액션→기록/점수 복원/재전송 거절, 명확한 시설→완료 알림/질문 없음.
- 권한/설정 제한 내역 저장, DB 재개방/읽음, 경고 지속/단절/정상/재발, 수동 완료/메모 수정 구별.
- 휴대폰 밝은/어두운 내역과 시스템 알림 화면, 실제 시스템 알림 탭→차량·이벤트 선택.
- 실제 Pleos 확인 배너에서 오인식 취소·닫기 두 흐름을 확인하고 기존 차량 preference 해시가 동일함을 확인했다.

실제 SDK 자동 세차 어댑터는 정확도(미터)·검증된 세차 구역·차량 이동 근거를 아직 확보하지 못해 연결되지 않았다. 휴대폰 위치 보완과 이동 구간별 과거 날씨 수집도 미연결이다. Bluetooth 실물 전달·잠금 화면·제조사 절전·재부팅은 미검증이다. 시험 입력을 이 기능들의 실수신 성공으로 바꾸지 않는다. [전체 결과](CARE_VALIDATION_RESULTS.md)를 함께 읽는다.

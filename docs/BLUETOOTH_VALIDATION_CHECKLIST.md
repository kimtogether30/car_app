# Bluetooth 일괄 검증 목록

2026-11-10. **실물 장치로 나중에 한 번에 확인할 미완료 목록.** 사용자는 현재 에뮬레이터만 사용 가능하다고 답했다. 실제 장치가 준비되기 전 반복해서 연결을 요청하거나, 계산/계측 테스트 성공을 Bluetooth 성공으로 바꾸지 않는다.

확인된 범위: Pleos 가상 어댑터 ON, 실제 SDK 일부 콜백, 시험 프레임→저장→ACK→Android 로컬 알림 테스트. **실제 차량 앱→무선 Bluetooth→실물 휴대폰→알림은 미검증.**

## 준비 및 결과 기록

- [ ] BT-01 지원 Pleos 시험 장비/차량과 Android 실물 휴대폰 준비. [공식 AVD 안내](https://document.pleos.ai/en/docs/connect/guide/getting-started/application-development/configure-pleos-connect-emulator)의 Bluetooth 동글 미지원 확인. 폰 두 대 시험은 전송 계층 검증이며 Pleos 성공과 구별.
- [ ] BT-02 양쪽 기기/OS/API, 앱 버전·빌드 종류·커밋, SDK/서비스 버전, 시험 시각 기록. 동일 프로토콜 v2·RFCOMM UUID 사용 확인.
- [ ] BT-03 기존 프로필·관리기록 백업 및 비교 기준 확보. `install -r` 사용, wipe/앱 데이터 초기화 금지.
- [ ] BT-04 페어링은 음악/통화 연결과 구별. 앱 데이터 소켓 연결·최초 메시지 저장·ACK까지 증거 확보.

## 권한·상대 기기·연결

- [ ] BT-05 주변 기기 CONNECT 권한 허용/거부/철회, Bluetooth OFF/ON 각각 확인. 실제 위치 보완 권한은 별도 시험.
- [ ] BT-06 사용자가 선택한 페어링 상대만 연결. 다른 페어링 기기·미페어링 기기·잘못된 상대는 데이터 수신/저장 금지.
- [ ] BT-07 앱 서버 시작→휴대폰 연결→프로토콜 확인→전체 스냅샷 저장→ACK 순서. 소켓만 열린 상태를 ‘데이터 연결됨’으로 표시하지 않음.
- [ ] BT-08 상대 앱 미설치/구버전, UUID/프로토콜 불일치, 연결 대기/타임아웃의 안내와 자원 해제 확인. 같은 v2라도 구버전이 오인식 취소 필드를 처리하는지 확인하고, 최신 양쪽 빌드의 결과와 구별.
- [ ] BT-09 범위 이탈/복귀, Bluetooth OFF/ON, ACL 재연결, 수동 종료/재연결. 마지막 데이터와 마지막 수신 시각 유지, 무한 재시도·폴링 없음.

## 메시지·ACK·재전송

- [ ] BT-10 실제 프레임 송신→휴대폰 저장→동일 차량ID/revision ACK 왕복 확인. 빈 값/0/기본100을 임의 정상값으로 만들지 않음.
- [ ] BT-11 ACK 유실·지연·중복: 최대3회/5초 재전송, 중복 저장/알림/기록 없음. 수신 저장 후 ACK 전 단절도 포함.
- [ ] BT-12 프레임 도중 단절/잘린 프레임/과대 프레임/잘못된 JSON: 불완전 자료를 적용하지 않고 재연결 후 정상 복구.
- [ ] BT-13 같은 메시지 반복/역순/과거 revision/늦은 응답: 설정·기록·현재 경고가 과거 상태로 돌아가지 않음.
- [ ] BT-14 양쪽 앱 프로세스 종료/재시작, 재부팅 후 마지막 스냅샷·미전송 요청·중복 방지 상태 복원. 서비스 실행 조건도 실제 OS에서 확인.
- [ ] BT-15 장부128건 초과로 여러 묶음 전송. 각 묶음 저장/digest ACK 후 다음 묶음, 중간 단절·재시작에도 누락/이중 반영 없음.
- [ ] BT-16 양쪽 시계 차이/과거 시각/미래 시각/시간대 변경. 원본 관측 시각 보존, 오래된 경고를 현재 경고로 보내지 않음.

## 휴대폰 최종 설정·기록

- [ ] BT-17 첫 연결 시 기존 차량 설정 가져오기. 같은 차량의 기존 휴대폰 설정이 있으면 유지하고 기본30으로 덮지 않음. 다른 차량의 기록과 섞이지 않음.
- [ ] BT-18 차량 설정 변경 요청→휴대폰 버전 확정→차량 사본 갱신. 휴대폰 변경도 연결 중 차량에 전달.
- [ ] BT-19 단절 중 차량 변경/여러 번 편집 후 재연결, 양쪽 동시 편집/오래된 base 버전 충돌. 최신 휴대폰 설정 유지, 대기/충돌 표시와 사본 확인.
- [ ] BT-20 수동 기록 추가/수정/삭제, 자동 기록 메모 수정/수동 전환, 같은 날짜 자동+수동 보완/별도 추가 선택. ID·완료 시각·visitId 유지.
- [ ] BT-21 차량 전환/동일 visitId가 서로 다른 차량에 존재하는 경우. 설정·기록·PendingIntent·알림·취소가 해당 차량에만 적용.

## 세차 확인 배너·오인식 취소

- [ ] BT-22 업로드 기준의 시설별 조건을 충족하면 먼저 세차 반영·재계산. 장소 구분이 애매한 적격 방문은 **‘세차하신 게 맞나요?’ / ‘잘못 인식함’**, 전용 셀프/명확히 분리된 세차 구역은 BT-37의 완료 배너. 실제 물세차 여부의 불확실함만으로 보류하지 않음.
- [ ] BT-23 컨베이어식 N 이동→D 출차와 정차식 P/N 여부와 별개인 실제 정차180초→차량 출차를 각각 재현. 모든 시설에 N 조건을 강제하지 않음.
- [ ] BT-24 주유만 함, 주유소 대기/옆 도로 통과, 세차 구역 체류180초 미만, GPS 흔들림, 휴대폰만 남는 경우: 조건 미충족이면 기록 생성 없음.
- [ ] BT-25 휴대폰 배너/시스템 알림의 ‘잘못 인식함’: 동일 visitId 취소, 이전 기준으로 재계산, 첫 기록이었다면 null. 앱 재시작 후에도 유지.
- [ ] BT-26 차량 배너에서 오프라인 ‘잘못 인식함’→재연결. 설정 버전 충돌과 별개로 취소가 휴대폰에 반영되고 오래된 스냅샷으로 부활하지 않음.
- [ ] BT-27 취소→동일 방문 재전송/중복/역순, 취소 직후 앱 종료, 재부팅: 취소/알림 중복 없음. 다른 새 방문은 정상 감지 가능.
- [ ] BT-28 배너 ‘닫기’/알림 스와이프/응답 없음: 세차 반영 유지. 앱 안 배너 닫기 상태 복원, 7일 취소 기간 및 기존 기록 삭제와의 구별 확인.
- [ ] BT-29 OS 알림 허용/거부·채널 차단·방해금지·앱 알림 설정 OFF. 시스템 배너 제한과 앱 안 확인 배너를 구별. HIGH 채널이어도 실제 heads-up 표시는 OS/사용자 설정에 따름.
- [ ] BT-30 ‘기록 보기’/알림 탭/이미 앱이 열린 경우의 이동, 한글 버튼·큰 글자·다중 알림·연속 방문에서 올바른 차량/기록 선택.

## 정비 알림·화면 꺼짐·휴대폰 위치 보완

- [ ] BT-31 실제 지원 경고의 원본 상태/색상/점멸/관측 시각이 전달됨. 미확인 차종별 규칙은 자동 활성화하지 않음.
- [ ] BT-32 워셔액 부족→지속→정상→재발, 경고 악화, 이미 해제된 과거 경고의 재연결. 미지원/권한 거부/오류/단절은 정상화나 정비 완료가 아님.
- [ ] BT-33 앱 백그라운드/화면 꺼짐/절전/제조사 배터리 정책/강제 종료에서 수신·FGS·재연결·알림의 실제 범위 확인. 미보장 구간을 명시.
- [ ] BT-34 휴대폰 위치 보완 어댑터·권한·FGS 구현 후, 차량 진입→차량 신호 중단→휴대폰 유효 체류→차량 재연결·출차 연결 확인. Bluetooth 단절을 시동OFF나 세차로 해석하지 않음.
- [ ] BT-35 양쪽 위치 공백·정확도 미제공·경계 불확실·휴대폰만 시설에 남는 경우. 누락 시간을180초에 더하지 않음.
- [ ] BT-36 실제 운영에서 저장량·전송량·재전송 횟수·배터리·메모리·중복 SDK 연결 여부 측정. 기존 Gradle/AVD 성능 제한 유지.

## 제공 디자인·알림 내역·세차 확실성

- [ ] BT-37 전용 셀프 세차장 및 주유 구역과 명확히 분리된 세차 구역에서 전체 체류·유형별 패턴·출차 충족 → ‘세차 완료!’. 시설 진입만/짧은 체류는 완료 아님. 검증된 구역 정보의 출처도 기록.
- [ ] BT-38 주유와 동선이 겹쳐 애매하지만 필수 세차 조건을 충족한 방문 → 우선 반영·질문 배너. ‘잘못 인식함’ 알림 액션/내역 액션 → 취소·점수 복원·재전송 방지.
- [ ] BT-39 제공 디자인 66종의 밝은/어두운 모드, 주유·세차·정비 조합, 복수 경고. 잘못된 부품 그림을 대신 쓰지 않으며 EV는 충전 문구 사용. 경고 미지원/자체점검/단절을 정상·수리 완료로 바꾸지 않음.
- [ ] BT-40 시스템 접힘/펼침/heads-up/잠금 화면과 실제 휴대폰 글자 크기·버튼 터치. OS 장식 영역과 제공 배너 이미지의 차이 확인. OS 설정으로 heads-up이 제한되면 별도 기록.
- [ ] BT-41 수신→내역 저장→시스템 게시 결과, 권한 거부/채널 차단/앱 설정 OFF에서도 내역 유지. 재시작·재부팅·페이지 이동·읽음 상태·취소 이력 및 차량 분리 확인.
- [ ] BT-42 동일 상태 지속/재전송→중복 없음, 명시적 정상→재발→새 알림, 여러 경고 동시 발생. 오래된 원본 시각/null 신호가 새 메시지로 갱신되지 않음, 양쪽 장치 시계 오차도 기록. 수동 완료 기록은 완료 알림, 최초 과거 기록 가져오기/메모 수정은 완료 알림 없음.
- [ ] BT-43 앱 종료/열림 상태의 알림 탭과 ‘알림 내역’ 버튼 → 해당 차량·이벤트 상세. 여러 차량/방문의 PendingIntent 혼선 없음. 알림 스와이프는 세차 취소가 아님.

## 한 번에 남길 결과 양식

실행마다 아래 표에 BT-ID별 **통과/실패/미지원/미구현/미실행**을 구분해 기록한다. 로그는 `build/diagnostics/bluetooth/<실행ID>/`에 보관하고, 원본 VIN·전체 MAC·좌표는 불필요하게 수집/공유하지 않는다. 이 문서가 점검 항목의 단일 목록이다.

| BT-ID | 장비·앱·OS 버전 | 실제 입력/동작 | 관측 결과·증거 파일 | 판정 | 남은 문제 |
| --- | --- | --- | --- | --- | --- |
| 미실행 | 실물 장비 없음 | 없음 | 시험 프레임 테스트만 별도 기록 | 미검증 | 실물 장비 준비 후 일괄 실행 |

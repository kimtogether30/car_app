# 세부 처리안·초기 시험값·미검증 항목

갱신일: 2026-11-09. 첫 문서 전달 이후 사용자가 요청한 여섯 쟁점의 구체화 방안을 모두 기록합니다. **이번 전달은 문서만 수정하며 앱 동작·SDK 설정·에뮬레이터를 변경하지 않습니다.**

## 1. 기준 요약과 변경 이력

| 쟁점 | 최신 기준 |

| 평균 주행거리 | 30km 예시 폐기, **20km/일** |

## 2. 위치 초기 시험 프로필

이 값은 공식 권장 정밀도나 검증된 감지 성공률이 아닙니다. 실제 관측 주기·정확도·지도 형상에 맞춰 시험한 뒤 버전별 설정으로 확정합니다.

| 항목 | 초기 시험값 / 처리 |
|---|---|
| 수집 | 후보 시설 근처에서5초 간격 요청. 요청 주기와 실제 수신 주기를 구분 |
| 신선도 | 위치 생성 후10초 이내. 전송 수신 시각으로 오래된 위치를 새것으로 만들지 않음 |
| 정확도 | 유효한 수평 정확도 값이10m 이하. 값 미제공을0으로 취급하지 않음 |
| 위치 구분 | 내부 / 외부 / 경계 불확실 |
| 진입 | 정확도 범위까지 구역 내부인 유효 관측을10초 연속 확인 |
| 공백<=15초 | 방문 후보 유지. 관측 없는 시간은180초에 넣지 않음 |
| 공백>15초 | 연속 체류 인정 중단. 유효한 휴대폰 위치로 이어진 경우는 실제 확인 구간만 이어 사용 |
| 출차 | 정확도 범위까지 외부인 관측을30초 확인하고 일관된 실제 이탈 이동 확인 |

위치 정확도 반경은 통계적 추정이며 실제 위치를 보장하는 울타리가 아닙니다. 좁은 세차기에서 이 조건이 성립하지 않을 수 있습니다. 단순100m 등 대형 원형 지오펜스는 후보 시설 탐색에만 사용하고 가솔린 주유 위치와 세차기 위치를 구분하는 근거로 사용하지 않습니다. 고정20m 출차나 GPS 한 번의 점프를 필수/충분 조건으로 쓰지 않습니다.

경계 불확실 관측은 진입·체류·출차의 증거에 넣지 않으며 외부로도 단정하지 않습니다. 수집은 이동·시설 인근일 때 필요한 수준으로 제한하고 성능·배터리 예산을 지킵니다.

**아직 실제 검증 필요:** 컨베이어 이동의 최소 거리·일관성·속도 근거, 정차 판정 신호, SDK 위치 정확도 제공 여부, 실제 수신 주기, 지도 영역·시설 유형. 미확인 값을 추측해 성공 처리하지 않습니다.

## 3. 180초와 수신 중단

- 컨베이어식: **구역 내부 체류에 N 상태의 컨베이어 이동 시간을 포함**. N이동·D전환·출차는 같은 방문의 일관된 순서로 확인.
- 정차식: **구역 안에서 정차가 확인된 유효 체류180초**. P/N만으로 정차 입증 금지.
- 둘 다 구역 밖 대기·주유 시간 제외. 수신 공백을 관측된 시간처럼 채우지 않음.
- 차량 신호 중단 전 구역 진입과 이후 휴대폰 위치·차량 재연결·출차가 연결돼야 함.
- 휴대폰 위치를 차량 위치로 단정하지 않음. 운전자가 휴대폰을 가지고 내린 경우 등 모순이 있으면 보류.
- 데이터 출처 전환·단절 시각을 보존. 단순 Bluetooth 단절을 시동OFF로 기록하지 않음.

## 4. 자동·수동 중복 기록

1. 자동 추정이 관리기록 한 건을 생성: `recordId`, `visitId`, 원본 자동 완료 시각, 출처, 취소 상태 보존.
2. 자동 메시지 재수신은 visitId로 같은 기록 갱신. 새 세차를 생성하지 않음.
3. 비용·메모 추가는 원래 자동 기록 편집. 이 경우 원본 자동 완료 시각 유지.
4. 같은 한국 날짜에 자동 기록이 있는데 수동 새 기록을 추가하려 하면 기존 기록 후보를 보여주고 `기존 기록 보완`/`별도 세차 추가` 선택 제공.
5. 기록이 여러 개면 사용자가 대상을 고르게 함. 날짜나 가상의 시간 허용폭으로 조용히 합치지 않음. 이 선택은 관리기록 추가 시에만 필요하며 모든 자동 감지에 답변을 요구하지 않음.
6. 자동 기록을 **명시적으로 수동 기록으로 전환**하면 해당 날짜 다음 날00시부터 차감하는 정책으로 재계산. 단순 메모 수정과 구별.
7. 합친 기록은 원본visitId를 유지해 취소·재전송 이력을 추적. 기존 기록 편집/삭제와 자동 추정의7일 취소를 별도 동작으로 관리.

기록과 알림을 구분합니다. 데이터 수정 시 과거 알림을 재발송하지 않습니다. 두 번 세차한 실제 기록은 유지하며 최근 유효 기준을 적용합니다.

## 5. 설정과 기록의 최종 기준은 휴대폰

| 휴대폰 앱 | 차량 앱 |
|---|---|
| 최종 washAlert·notifications 저장 | 마지막 동기화 설정 사본 |
| 최종 관리기록·청결도·알림 판단 | 차량 신호·방문 근거 수집 |
| 설정 변경 요청 승인·버전 증가 | 요청·미전송 데이터 보관 |

- 차량 앱의 설정 변경은 요청으로 보내고 휴대폰 저장·버전 응답 후 확정. 단절 중에는 동기화 대기.
- 휴대폰에서 바꾼 설정은 차량에 새 버전으로 전달. 과거 사본이 최신값을 덮지 않음.
- 차량ID·연결 대상·요청ID·설정 버전을 사용. 기기 시간만 비교하는 마지막 쓰기 우선 정책을 쓰지 않음.
- 최초 연결에서는 기존 차량 설정을 가져와 휴대폰 기준으로 확정. 기존 휴대폰 설정이 이미 있으면 조용히 덮지 않고 기존 유지 또는 가져오기 선택. 기본30으로 초기화 금지.
- 모든 화면과 캐릭터는 동일한 계산 결과를 사용. 차량이 임시 로컬 값을 보여주더라도 최종 상태와 혼동하거나 별도 휴대폰 알림을 만들지 않음.
- 여러 차량의 설정·기록·알림 분리. 이번 문서는 사용자 계정 서버·다중 휴대폰 동시 편집을 새 기능으로 요구하지 않음.

## 6. 원본 위치와 계산 장부 보관

| 종류 | 보관 |
|---|---|
| 원본 상세 위치 | 기본30일. 사용자 삭제 경로 보장 |
| 세차 기록·연결visitId·취소 흔적 | 해당 차량 관리기록과 함께 유지 |
| 비위치 계산 장부 | 과거 기록 수정·삭제·취소를 재계산할 수 있도록 차량 기록과 함께 유지 |
| 중복 방지·발송 내역 | 동기화·재시작·복원 시 중복을 막을 최소 상태 유지 |

장부 필드: 시간 구간·차량ID·원본 이벤트ID, 실제/추정 거리·근거 상태, 날씨 분류·보정 마감, 기본 차감·강수 추가·**하루 한도 적용 전 먼지 추가값**, 정책 버전·순서. 원본 경위도를 장기 장부에 복제하지 않습니다.

단순 일별 최종 점수만 남기면 자동세차의 당일 시점 및 삭제 후 먼지 한도 재배분을 복원할 수 없으므로 금지합니다. 구간 압축은 세차 경계·기존 계산 결과를 보존하며 압축 전후 재계산 동등성을 검증해야 합니다. 기준을 가로지르는 구간은 분리 근거가 있는 부분만 사용하고, 없다면 해당 경계 구간을 차감에서 제외하는 기존 정책을 따릅니다.

30일은 위치 삭제 기준이지 재계산 기능 만료일이 아닙니다. 차량·사용자 데이터 삭제 시 관련 장부도 삭제하고 다른 차량 자료는 보존합니다. 저장량은 시험·측정하며 원본 이벤트를 무제한 이중 저장하지 않습니다.

## 7. 정비 경고 규칙표

전체 대상 목록은 MAINTENANCE_ALERT_POLICY에 있습니다. 다음은 구현할 규칙표의 요구사항이며, 임의 지속시간을 모든 차량에 적용하는 근거가 아닙니다.

| 필드 | 요구 |
|---|---|
| 적용 범위 | 차종·연식·동력·SDK 버전·capability |
| 원본 | 타입·ON/OFF/BLINK·색상·액량 상태·관측시각 |
| 전제 | 엔진/차량 운전 상태 등 해당 경고의 정상·이상 구분에 필요한 신호 |
| 발송 | 공식 의미에 맞는 조건·필터·심각도·문구 |
| 해제·재발 | 유효OFF/NORMAL·재발·악화 구분 |
| 근거·상태 | 공식URL/설명서 위치, API 검증, 에뮬레이터·실차 검증, 활성화 여부 |

| 그룹 | 세부 처리 |
|---|---|
| ENGINE_OIL_PRESSURE | 시동 전 점등과 실제 운행 이상 구분. 엔진 작동 전제를 모르면 확정적 고장 판단 금지 |
| ENGINE_TEMPERATURE, H2_LEAK 등 | 이상으로 확인된 긴급 상태를 일반 알림 지연 때문에 늦추지 않음. 정확한 조치는 해당 차량 공식자료 확인 |
| ESC | 정상 개입 점멸을 고장 알림으로 만들지 않음 |
| ELECTRONIC_PARKING_BRAKE | 정상 상태와 시스템 이상 구분에 필요한 색상·상태 의미 확인 |
| ENGINE, LOW_VOLT_BATTERY, ABS, MDPS, TPMS, AIRBAG | 시동 점검·운전 상태·점멸별 의미를 차량별 대조 후 활성화 |
| AFS, LED_HEADLAMP, PARTICLE_FILTER, SCR, WATER_SEPARATOR | 타입만으로 고장 원인 확정 금지. 필요한 점검/사용자 조치와 정상 표시 구분 |
| EV/HEV/FCEV/EREV_SYSTEM, H2_SENSOR | 해당 동력·차량 공식 경고 의미와 신호 확인 |
| 오일·액량3종 | 지원되는 NORMAL/LOW/CRITICALLY_LOW/HIGH를 구별, ERROR는 이상 액량 아님 |
| 워셔액 | 유효한 부족 상태에 보충 알림. 엔진오일·브레이크액에 동일 보충 문구 복사 금지 |

공통: 유효한 최초 이상 한 번, 지속 중복 없음, 악화는 새 알림 가능, 정상 후 재발은 새 알림. OFF/NORMAL만 해제로 인정하고 단절·미수신은 해제가 아닙니다. 정상화는 정비 완료가 아닙니다. 긴급도는 색상 하나로 결정하지 않고 모든 경고에3초/5초 필터를 공통 적용하지 않습니다.

필요 신호·공식 의미가 미확인인 항목은 `규칙 미검증/자동 정비 알림 보류`로 기록합니다. 전체 타입을 지원 대상으로 준비하는 것과 모든 항목을 즉시 활성화하는 것은 다릅니다. 이 문서가 차량별 임계시간과 진단 문구까지 검증했다는 뜻은 아닙니다.

- 정책은 위와 같이 정해 구현 가능하나 센서·지도·Bluetooth 지원은 실수신 확인 전 미검증.
- 시험 프로필 설정값과 SDK 실제 관측값, 판정·보류 이유를 함께 기록.
- 오판·누락을 구분해 측정. 조건 완화로 성공처럼 보이게 만들지 않음.
- 시연 시간 가속·시험 데이터와 실제180초·실제SDK 수신을 구분.
- Android 공식 API 설명은 Pleos 권한·기능 제공을 보장하지 않음.

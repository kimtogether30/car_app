# 친구 PC 수신 검증·시뮬레이션 계획

2026-11-10 후속 지침: 실제 Bluetooth 점검은 [일괄 검증 목록](BLUETOOTH_VALIDATION_CHECKLIST.md)에 모아 나중에 실행한다. 시설별 조건 충족 후에는 세차로 우선 반영하고 ‘세차하신 게 맞나요?’ 배너의 ‘잘못 인식함’으로 되돌린다. 정차식/P 기반 세차에 컨베이어식 N 조건을 적용하지 않는다.

**상태: 실행 전 체크리스트. 아래 항목은 이번 문서 작업에서 실행하지 않았습니다.**

최신 시험 프로필과 설정·기록 정책은 [세부 처리안](CARE_IMPLEMENTATION_DETAILS.md)을 기준으로 합니다. 아래 체크리스트는 성공 결과가 아니라 구현자가 수행할 검사입니다.

수신 가능성 확인은 시연 직전에 미루지 말고 구현 초기에 실시합니다. 현재 PC 성능 제한과 루트 AGENTS.md를 준수합니다. 에뮬레이터·Gradle·대용량 작업을 불필요하게 동시에 실행하지 않습니다.

## 1. 결과 수준 구분

| 검증 | 입증 범위 |
|---|---|
| 계산 단위 테스트 | 입력 대비 로직 결과 |
| 시험 데이터 공급자 | 시나리오 처리·UI, 실제 SDK 수신 아님 |
| Pleos 콘솔→실제 SDK 콜백 | 에뮬레이터 서비스 연동, 실차 성공 아님 |
| 두 물리 장치 Bluetooth | 해당 장치 전송, Pleos 실차 환경 성공과 구분 |
| 지원 차량·시험 장비 | 해당 환경의 실제 신호·통신 |

기본값 0·null·가짜100을 SDK 성공으로 취급하지 않습니다. 실제·시험 공급자를 분리하고 시연 데이터임을 표시합니다.

## 2. 최우선 수신 확인

- [ ] 설치 SDK 버전·서비스 버전·에뮬레이터 버전 기록.
- [ ] 공식 기기 프로필과 Cold Boot 사용. 무단 RAM·해상도 축소나 데이터 wipe 금지.
- [ ] 콘솔에서 기어 P→N→D 변경 후 `getCurrentGearSelectionState`/구독 콜백의 실제 값·지연 확인.
- [ ] 위치 생성 시각·갱신 주기·정확도 확보 여부 확인. 위치 정확도 필드가 없으면 이를 있다고 가정하지 않음.
- [ ] 누적거리·트립 거리의 단위·갱신·0의 의미 확인.
- [ ] 짧은 저속 이동을 위치·거리 신호가 실제로 구분하는지 확인. 컨베이어 재현 데이터는 실차 검증과 구분.
- [ ] 대상 정비 경고의 capability·읽기 권한·점등/점멸/색상 수신 확인.
- [ ] 엔진오일·브레이크액·변속기 오일·워셔액 실제 API 응답 확인.
- [ ] 일반 권한 조회와 특권 구독을 구분. 미지원 기능은 명시적으로 비활성화.

## 3. 휴대폰·Bluetooth

- [ ] Android 실기기의 위치 권한·화면 꺼짐·백그라운드 수신 확인.
- [ ] 앱 수준 연결 대상 확인, 승인·재연결·잘못된 기기 연결 처리.
- [ ] 차량 앱 측 메시지→휴대폰 수신→ACK 전체 확인.
- [ ] 단절·중복·역순·앱 재시작·재전송·시각 불일치 처리.
- [ ] 휴대폰이 최종 washAlert·notifications를 관리하고 차량 변경 요청→버전 회신·오프라인 대기·최초 설정 가져오기를 검증.
- [ ] 이미 저장된 휴대폰 설정이 있을 때 기존 차량 설정으로 무단 덮어쓰기 없음.
- [ ] Android 알림 권한 허용/거부와 수신·액션 확인.
- [ ] 차량 데이터 중단을 휴대폰 위치가 보완한 뒤 차량 재연결·출차로 방문 연결 가능한지 확인.

Pleos 공식 에뮬레이터 안내에는 AVD Bluetooth 동글 미지원 제한이 있습니다. 사용 버전에서 재확인하고, 지원되지 않으면 SDK 검증과 Bluetooth 실기기 검증을 분리합니다. 폰 두 대 통신 성공을 Pleos 통신 성공이라고 보고하지 않습니다.

## 4. 계산 시나리오

| 시험 | 예상 결과 |
|---|---|
| 수동 세차 11/1, 11/2 00시 | 100%, 수동 당일 제외 |
| 같은 기록, 실제 데이터 없이 11/9 00시 | 86%: 7일×20km×0.1 |
| 실제 주행 30km, 그중 비10km | 5%p 차감 |
| 실제 미주행 확인 24시간 | 기본 차감0 |
| 주행 미확인 24시간 | 기본 차감2%p |
| 실제30km가 해당 하루 평균20km를 대체 | 기본 차감2→3%p, 합계5로 만들지 않음 |
| 실제0km가 같은 평균 추정을 대체 | 기본 차감0으로 보정, 세차 완료 생성 안 함 |
| 평균 거리만 있고 비 예보 있음 | 기본 차감만 |
| 실제 구간의 PM 두 종류가 모두 높음 | 높은 보정 하나, 추가분 하루2%p 한도 |
| 비·눈·PM 동시 해당 | 기본+눈, 비·PM 추가 제외 |
| 72시간 이내 날씨 후수신·중복 | 한 번 보정 |
| 세차일 모름 | null·퍼센트 알림 없음 |
| 첫 자동 세차 후 취소·이전 기준 없음 | null 복귀 |
| 과거 수동 세차 수정·삭제 | 최근 유효 기준부터 재계산 |
| 사용자 임계값25, 표시점수25 | 설정·권한 허용 시 필요 알림 한 번 |
| 동일 주기 앱 재시작·데이터 보정 | 필요 알림 중복 없음 |

## 5. 감지 시나리오

- [ ] 세차장 옆 도로 통과: 초기화 없음.
- [ ] 주유소에서 주유만 함: 초기화 없음.
- [ ] 세차 구역에서 180초 미만: 초기화 없음.
- [ ] 유효 구역·180초·컨베이어 N이동·D출차: 자동 추정 한 번.
- [ ] 유효 구역·180초·정차식 출차: 자동 추정, 실제 세차 증명이라고 표시 금지.
- [ ] GPS 흔들림·경계 반복: 가짜 컨베이어·중복 방문 없음.
- [ ] 차량 중단→휴대폰 체류→차량 재연결·출차: 근거가 유효하면 한 방문으로 판단.
- [ ] 양쪽 위치 공백: 미확인 시간을 채우지 않고 보류.
- [ ] 휴대폰만 세차장에 남고 차량은 이탈: 휴대폰만으로 초기화 금지.
- [ ] 지연 감지 후 초기화: 완료 이후 차감 반영.
- [ ] 자동 기록 취소→동일 메시지 재수신: 재초기화 없음.
- [ ] 같은 세차 수동 기록 추가: 연결 근거로 중복 방지.

## 5-1. 최신 세부안 회귀 검증

- [ ] 시험 프로필(5초 요청·10초 신선도·10m 정확도·10초 진입·15초 공백·30초 출차)을 설정 파일/객체로 분리하고 실제 수신 간격과 대조.
- [ ] 정확도 미제공·오래된 위치·경계 중첩은 내부 체류로 인정하지 않음.
- [ ] 구역 밖30초라도 실제 이동 근거가 없으면 가짜 출차로 확정하지 않음.
- [ ] 컨베이어식180초에 유효한 구역 내 이동 시간 포함, 정차식에는 정차 시간만 포함.
- [ ] 공백15초 이하 후보 유지하되 누락 시간은 체류에 더하지 않음.
- [ ] 차량 중단을 휴대폰 유효 위치로 보완한 경우와 양쪽 미수신인 경우 구분.
- [ ] 자동 기록의 메모 수정은 자동 시점 유지. 명시적 수동 전환은 다음 날00시 기준 재계산.
- [ ] 같은 날 기존 기록 보완/별도 세차 추가 선택, 두 번의 실제 세차 보존.
- [ ] 동일visitId 재전송·취소 후 재전송·앱 재시작에서 기록 중복/부활 없음.
- [ ] 원본 위치30일 삭제 후에도 장기 장부로 과거 기록 수정·삭제 재계산 가능.
- [ ] 먼지 하루 한도 적용 전 값 보존, 기록 삭제 후 해당 날짜 재계산 결과 일치.
- [ ] 장부 압축 전후 계산 동일, 차량 데이터 삭제는 해당 차량에만 적용.
- [ ] 정비 규칙표가 공식 근거·필요 신호·검증 상태·활성화 여부를 구별하고 미확인 항목을 자동 활성화하지 않음.

## 6. 정비 시나리오

- [ ] ON/BLINK/색상·정상 작동/이상 구분.
- [ ] 시동 자체 점검 점등을 고장으로 오인하지 않음.
- [ ] 액량 LOW/CRITICALLY_LOW/HIGH/NORMAL/ERROR 처리.
- [ ] 정상화는 정비 완료·오일 교체 완료가 아님.
- [ ] 미지원·단절은 정상으로 바뀌지 않음.
- [ ] 지속 경고 중복 없음, 악화·해제 후 재발 처리.
- [ ] 이미 해제된 과거 경고 재연결 시 현재 알림으로 발송하지 않음.

## 7. 시연 준비 및 결과 기록

실제180초 검증과 발표용 시간 가속·기록 재생을 구분합니다. 발표용 데이터에는 시험 출처를 표시합니다. 실제 날씨가 없는 날은 계산 시험 데이터로 비·눈을 재현하되 실측 강수 수신이라고 설명하지 않습니다.

아래 형태로 결과를 별도 문서에 남깁니다.

| 항목 | 환경·버전 | 지원/권한 | 받은 값·시각 | 결과 | 남은 문제 |
|---|---|---|---|---|---|
| 기어/위치/거리/경고/Bluetooth 등 | 미실행 | 미확인 | 없음 | 미검증 | 테스트 필요 |

빌드·관련 단위 테스트를 수행하되 문서 변경만 받은 시점에는 기존 검증 성공을 새 기능 성공으로 재사용하지 않습니다. 실제 수신 불가를 발견하면 감지 범위를 수정하고 이유를 기록합니다.

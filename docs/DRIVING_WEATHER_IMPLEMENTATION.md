# 주행 구간 → 시간별 날씨 → 청결도 연결 구현

2026-11-11. 앞선 `WEATHER_INTEGRATION_HANDOFF.md`의 ‘친구 구현 대상’ 중 아래 연결을 이번에 코드로 적용했다. 주간 예보 UI/세차 날짜 추천/화면 갱신 정책은 이후 `WEATHER_UI.md`의 2026-11-12 구현으로 연결했다.

## 실제 실행 경로

1. `SharedVehicleConnection`: 기존 차량 SDK 수집 소유자가 있고 FUSED_LOCATION 권한이 허용되면 별도 읽기 전용 Pleos 위치 구독을 연다. 수집 소유자가 모두 해제되면 위치도 해제한다. 오류/권한 거부 시 위치를 만들지 않는다. SDK 버전/기기 프로필/차량 제어는 변경하지 않음.
2. `VehicleCareRuntime.payload` → `CareJournal.observeDistance` → `DistanceAccumulator`: 정상 누적거리 SDK 응답과 최근 위치로 구간을 생성한다. 다른 경고의 재게시로 오래된 누적거리가 다시 들어와도 신규 수신으로 세지 않는다.
3. 누적거리 동일은 `stationary=false`, 거리 0의 잠정 구간이다. 기준 시각은 유지하며 같은 ID를 확장한다. 증가 시 같은 ID의 잠정 구간을 실제 증가분으로 대체해 이중 차감하지 않는다. 구간이 무선으로 먼저 전달됐어도 더 최신 구간으로 대체한다. 오래된 짧은 재전송은 무시한다.
4. 실제 거리가 정상 수신된 구간만 평균 거리 차감을 덮는다. 미수신 시간은 기존 20km/일 보완. 단절/재시작/차량 변경/음수·비정상 증가를 억지로 잇지 않는다. 새 SDK 응답 간격이 15분 초과이면 새 기준점으로 시작하며 그 공백은 평균 보완한다.
5. 5분 이내, 시작/종료 위치 각각 60초 이내, 직선 5km 이내, 동일 시간 구간 조건을 충족하면 종료 위치를 대표 위치로 보관한다. 비정상 점프를 줄이기 위해 `300km/h × 구간 시간 + 100m`의 넓은 상한도 적용한다. 실제 속도를 측정/진단하는 규칙은 아니다. 기본 차감은 날씨 적격 실패와 무관하게 유지한다.
6. 기존 BT `intervals`에 대표 위치를 포함해 휴대폰으로 전달한다. `CareExchange.receive`가 저장·응답한 후 비동기 `DrivingWeatherSync`가 시간별 API를 조회한다. BT ACK를 HTTP 응답 때문에 기다리게 하지 않는다.
7. 시간 구간이 끝난 뒤에만 조회. 강수는 종료 시각의 직전 1시간 합계, PM은 시작 시각 값으로 다음 1시간 대표. 결과는 `HourWeather.hourStart`에 구간 시작으로 정규화한다.
8. `attachWeather`는 이미 저장된 실제 구간의 날씨만 추가한다. 과거 72시간/원 구간 ID·시각·거리 확인, 재수신/역순/다른 차량 중복 방지. 완료 날씨는 저장해 재계산 시 같은 데이터를 사용한다.
9. 점수·기존 캐릭터·알림 재평가. 기존 휴대폰 화면은 데이터 재계산 신호만 구독하며 레이아웃 변경 없음. 기존 BT 응답에 `weatherIntervals`를 넣어 차량의 동일 구간에도 날씨를 반영한다. 차량이 결과를 재전송하면 수신 완료로 표시해 128개 초과 미전달 결과도 다음 응답으로 진행한다.

## 차감과 누락

- 기본 0.10%p/km, 눈 ≥0.1cm +0.40%p/km, 비+소나기 ≥0.1mm +0.20%p/km. 눈 우선.
- 강수 없음이 확인된 경우에만 PM 추가. 기존 80/35·150/75 경계, 0.03/0.06%p/km, 먼지 추가 최대 2%p/한국 날짜. 미량 강수도 ‘강수 없음’으로 바꾸지 않는다.
- 날씨 조회 실패/구조 오류/누락을 맑음으로 바꾸지 않는다. 비·눈 유효 값이 있으면 해당 보정은 가능하지만 강수 없음이 확인되지 않으면 PM 보정 불가. 대기질 조회 실패가 비·눈 보정을 막지는 않는다.
- 날씨가 없는 경우 기본 거리는 차감한다. 평균 거리·주차 중 날씨에는 추가 차감하지 않는다. 미래 일별 예보를 가져와 현재 점수를 미리 깎지 않는다.
- 비/눈/맑음 모델값을 저장한 구간은 반복 조회로 자꾸 바꾸지 않는다. 완성된 강수 자료를 받지 못한 구간은 제한적으로 재시도하며 기한 만료 시 기본 차감만 유지한다.

## 호출·성능 범위

- 차량별 한 개 비동기 작업, 외부 API는 전체 차량에서 직렬 실행. 한 번에 최대 24개 구간 처리. 미완료/미공개/실패 구간이 있으면 10분 뒤 재시도하며 72시간 경과 시 종료한다. 프로세스 종료 후에는 다음 실제 수신 또는 앱의 기존 refreshAll에서 재개한다. OS가 백그라운드 실행을 막는 동안 수집/조회 성공을 보장하지 않는다.
- 내부 모델 요청·캐시는 0.01도 셀 중심(대략 1km), 시간별로 공유, 최대 64개 메모리 응답. 지역별 모델 추정치이며 1km 관측 해상도를 뜻하지 않는다. 주간 예보 화면 갱신 정책과 별개다.
- 날씨 API HTTP는 IO에서 실행, 타임아웃/응답 크기 제한. 개인 좌표·원시 응답 로그 없음. 장부에는 주행 구간 대표 위치가 들어가며 Android 백업 제외 설정은 유지한다. 전체 경로 추적은 추가하지 않는다.
- 누적거리 단위는 기존 `MaintenanceStore`의 확인된 km/m/mi 설정이 필요하다. SDK 단위를 임의 추정하지 않는다. 단위 미확인 시 실제 거리 연결 없이 기존 평균 보완으로 남는다.

## 무엇을 검증해야 하나

- JVM: 실제 거리 증가, 동일값·캐시 재게시·단절, 위치 유효성/시간 경계, 실제 API의 종료 시간 매칭, 눈 우선/미량 강수/PM 상한, 실패·누락·72시간 검증.
- Android verification 앱: 잠정→최종 구간 교체, 중복/역순, 원시 프레임이 보완 날씨를 지우지 않음, 양방향 날씨 결과 전달, 차량 분리, 128개 초과, 세차 기준 취소 재계산.
- **실제 Pleos 위치/거리 수신, 실행 중단 후 재수신, 화면 숨김, 물리 BT 왕복은 별도 미검증**. 에뮬레이터 주입/HTTP 조회 성공이 이를 입증하지 않는다. BT-48/49에서 함께 실행한다.
- SDK 설명서는 Android의 일반 foreground/background 위치 정책 동작을 별도 보장하지 않으므로 우회하지 않는다. 실제 SDK/OS가 위치를 주는 범위에서만 날씨 보정이 가능하다. https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/FusedLocation/intro

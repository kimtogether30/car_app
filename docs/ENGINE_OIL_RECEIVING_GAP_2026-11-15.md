# 엔진오일 정비소 수신 공백 추정 — 2026-11-15

사용자 최신 요청으로 세차와 같은 동일 장소 재수신 추정을 엔진오일에도 허용했다. 실제 전원 OFF/ON 미지원이어도 이 경로는 동작할 수 있다. 이 변경은 실제 시동 신호 지원을 추가한 것이 아니다.

## 적용 흐름

1. 지도에서 구역이 구분되는 정비소 안의 마지막 실제 차량 정차 위치를 차량 ID별로 저장한다.
2. 마지막 유효 정차 관측부터30분 이상 공백 뒤 같은 시설의20m 이내에서 신선한 차량 속도0·기어·위치를 받으면 체류로 추정한다. 계속 수신되는 정차 관측은 기준을 갱신하므로 연속 주차는 공백을 만들지 않는다.
3. D·실제 이동으로 구역을 나간 후 다음 차량 정차를 확인한다. 출차 후 다시 안으로 들어오면 이전 출차 후보를 무효화한다.
4. 알려진 교체 날짜가 있으면 가혹 주기 도달이 필요하다. 날짜 미상은 첫 기록 확보 예외다.
5. 먼저 `ENGINE_OIL / EstimatedOilVisit`을 기록한다. 무응답은 유지하고 부정 응답은 취소하며 같은 방문 재전송으로 복원하지 않는다.

## 증거·호환성

전원 확인은 `AAOS_IGNITION_STATE`, 공백 추정은 `SAME_PLACE_RECEIVING_GAP`로 분리한다. 기존 전원 방문의 직렬화/ID는 보존한다. 새 방문 ID는 `oil-gap:`으로 구분한다. 기록 상세에도 “수신 공백 … 시동 확인 아님”을 남긴다. 실제 OFF/ON을 거짓으로 생성하지 않는다.

공백 전 기준·시설 구역·미완료 방문은 기존 차량별 저장소에 저장하므로 객체/프로세스 재생성 후 이어받는다. 위치/속도/기어 원본 시각을 검사하고 폰 위치·캐시/역전·경계/시설 중첩·관측된 이동/이탈은 공백 근거로 인정하지 않는다. 초기 Loading/NoData는 정차로 보지 않되 구역 안의 마지막 실제 정차 기준을 보존한다.

위치 정확도 미제공은 세차처럼 미상으로 유지하고 지도 경계 버퍼를 적용한다. 알려진 정확도30m 초과는 제외한다. 최대 사이클24시간, 동일 위치20m와 정확도30m는 구현 시험 기준이며 실차 정확도나 작업 완료를 보증하지 않는다.

기존 위치 수신 소비자를 재사용한다. 추가 타이머·SDK 연결·무선 폴링을 만들지 않는다. 정비소 지도 조회는 기존15분 캐시·실패60초 재시도 제한을 재사용한다. 원본 좌표를 로그로 남기지 않는다.

## 검증 범위

- 두 앱 빌드·린트 통과, 단위 검사149개 실패0.
- S7 격리 앱 저장소 fixture14개 통과: 정확히30분,29:59, 같은 시설/다른 시설/중첩,20m 초과, 폰 위치, 연속 정차 수신, 이동/이탈, 초기 NoData, 객체 재생성, 출차/다음 정차, 출차 후 재진입, 주기 도달/미도달/미상, 취소/중복/재전송.
- 실제 차량 전원·실제 정비소30분 체류·S24↔S7 무선 왕복을 새로 검증한 결과가 아니다. 실제 장소에 지도 구역이 없거나 신선한 차량 위치/속도/기어가 없으면 자동 기록하지 않는다.

시동 여부와 중간 이동을 직접 알 수 없으므로 작업 완료는 항상 취소 가능한 추정이다. 기존 실제 전원 미지원 진단 결과는 그대로 유효하지만, 그것만으로 이 추정 경로까지 비활성화하지 않는다.

최종 APK는 S7(휴대폰 앱)과 Pleos AVD(차량 앱)에 데이터 보존 설치했다. S7 verification 앱은 검사 후 데이터 보존 비활성화했다. 원시 결과는 Git 제외 `build/verification/oil-resume-device-results.txt`, 빌드 결과는 `oil-resume-build.log`에 있다.

# HEV 주유·충전 판단 및 재알림 기준 인계

작성일: 2026-11-10 · 코드 확인 기준: `90cf848`

**2026-11-12 진행 상태:** 일반 HEV의 연료 퍼센트만 사용하는 판단은 차량·휴대폰 알림·캐릭터에 반영했습니다. **재알림 회복(T+10%p / 별도 SDK 조회 / 30초 / 3회)은 사용자 요청으로 이번 수정에서 제외하며 친구가 구현합니다.** 아래 내용은 합의한 목표 정책이며, 모든 항목이 구현되었다는 뜻은 아닙니다. 이번 변경 범위는 `REVIEW_FIXES_2026_11_12.md`를 확인하십시오. 기존 세차·정비 문서는 유지하며, 연료 판단에서 충돌하는 예전 규칙보다 이 문서의 최신 합의를 우선합니다.

## 1. 지원 범위

| 동력 방식 | 주유·충전 필요 판단 |
|---|---|
| 휘발유·경유 | 유효한 연료 잔량 |
| 일반 HEV | **유효한 연료 잔량만 사용** |
| EV | 구동 배터리 잔량. HEV 전용 정책과 혼동하지 않음 |
| PHEV·수소차 | 차량 선택 목록·이번 지원 범위에서 제외 |

차량 목록을 나중에 정리할 때 기존 PHEV·수소차 사용자 기록을 삭제하거나 HEV로 자동 변환하지 않습니다. 미지원 안내와 재선택 경로를 제공합니다. 이번 문서 추가만으로 목록이 바뀌지는 않습니다.

HEV 배터리 SOC는 주유·충전 필요 알림 및 에너지 부족 캐릭터의 판단에 사용하지 않습니다. 필요 시 상세 정보로 표시할 수 있지만 충전소 방문을 권하지 않습니다. HEV 시스템 이상·배터리/충전계통 이상은 기존 **정비 알림** 정책대로 별도 처리합니다. 정비의 12V 충전계통 경고와 외부 충전 필요 알림을 구분합니다.

## 2. 잔량 수신·전달

`차량 SDK 정수 잔량 → 차량 앱 같은 값 → Bluetooth 전달 → 휴대폰 앱 같은 값`

- `getFuelPercent()`와 `FuelPercentListener.onFuelPercentUpdated()`의 실제 설치 SDK 시그니처는 정수값을 사용합니다.
- **0~100 정수**를 그대로 사용합니다. 0은 정상적인 유효 잔량값입니다.
- 이 경로에서는 임의 추정·소수점 보정·추가 반올림을 하지 않습니다.
- null/범위 밖/오류/미지원/권한 거부/미수신을 0이나 정상으로 바꾸지 않습니다.
- 미수신 상태의 잔량 숫자는 공란, 새 주유 알림 없음. 앱 수신 시각·연결 상태·실제/시험 출처는 내부적으로 구분합니다.
- 연결이 끊긴 뒤 저장된 값을 새로 받은 값으로 표시하거나 회복 확인에 재사용하지 않습니다.
- 중복 Bluetooth 메시지·화면 재표시를 새 SDK 수신으로 세지 않습니다.

센서 내부 보정이나 새 측정/서비스 저장값 여부를 알아야만 기본 기능을 만들 수 있는 것은 아닙니다. SDK가 주는 값을 그대로 사용합니다. 공개 인터페이스의 콜백에 센서 측정 시각이 포함된 것으로 가정하지 않고 앱 수신 시각을 측정 시각으로 부르지 않습니다. 공식 문서·시그니처에서 일정 갱신 주기나 변동 제거 보장까지 확인한 상태는 아닙니다.

## 3. 주유 필요 알림·캐릭터

- 기존 사용자 설정 `fuelAlert` 사용. 기본20%, 현재 범위5~40%,5단위 보존.
- **유효한 연료 잔량 <= 사용자 설정값**일 때만 주유 필요입니다.
- 차량의 LOW_FUEL 경고는 주유 필요 알림·캐릭터·아이콘·복합 상태 판단에 사용하지 않습니다.
- 실제 잔량이 설정값보다 높으면 차량 LOW_FUEL 경고가 있어도 베모링 주유 경고 없음.
- 잔량이 없으면 LOW_FUEL 경고만으로 대신 알리지 않습니다. 실제 정비 경고는 별도 정책 유지.
- 최초 연결 시 이미 기준 이하이면 알림이 켜져 있고 발송 가능한 경우 한 번 발송.
- 같은 부족 상태 지속 중에는 반복 발송하지 않습니다. 부분 주유도 실제 잔량 그대로 표시하며100% 초기화 금지.
- 설정 변경·알림 재활성화는 현재 상태 평가. 같은 부족 구간의 기존 발송 이력은 보존해 설정 변경으로 재발송을 우회하지 않습니다.
- 알림 켜기/끄기 및 OS 권한 준수. OS에서 실제 게시하지 못한 요청을 성공 발송으로 기록해 이후 정상 알림이 영구 누락되지 않게 구별합니다.

캐릭터의 주유 필요도 같은 임계값으로 판단합니다. 단, **10%p 회복 절차는 알림 재무장용이며 캐릭터 상태 해제용이 아닙니다.** 설정20%에서21%를 유효 수신하면 주유 필요 범주는 해제됩니다. 다른 세차·정비 필요가 있으면 기존 복합 색상 규칙대로 최종 캐릭터를 결정합니다. 미수신을 주유 완료나 차량 정상으로 해석하지 않습니다.

## 4. 재알림 회복: +10%p / 30초 간격 / 3회

사용자 설정을 T라고 할 때 **T+10%p 이상**의 연료값을 최소30초 간격의 서로 다른 SDK 조회 성공 응답으로3회 확인합니다. 첫 번째부터 세 번째까지 최소60초 필요합니다.

1. 구독 수신 등에서 회복 후보를 발견하면 별도 연료 조회 확인을 시작합니다.
2. 첫 성공 조회값>=T+10이면1회. 다음 조회는 이전 인정 응답 후 최소30초 지나 요청합니다.
3. 두 번째·세 번째도 성공 및>=T+10이면 인정. 같은 값(예:30,30,30)이어도 서로 다른 실제 SDK 조회 성공이면 가능합니다.
4. 세 번째까지 충족하면 재알림 준비 상태를 저장합니다.
5. 이후 유효 잔량<=T이면 새 주유 필요 알림을 한 번 보내고 다음 회복을 기다립니다.

이는 실제 센서 독립 측정3회나 실제 주유 완료를 입증하지 않습니다. **앱에서 조회값이60초 이상 높은 수준으로 재확인됐다는 반복 알림 방지 정책**입니다. +5%p 제안은 폐기하며 +10%p가 최신 합의입니다.30초·3회는 앱 초기 운영 기준으로 테스트하고 임의로 계속 변경하지 않습니다.

## 5. 확인 중 예외

- 어느 유효 수신에서든 값<T+10이면 확인 취소. 단순히30초 기다린 것을 성공으로 세지 않습니다.
- 조회 오류·미수신·연결 끊김은 확인 중단, 다음 유효 후보부터 새로 시작.
- 미완료 확인 횟수는 앱/세션 재시작 시0. 완료된 재알림 준비 상태와 발송 상태는 차량별로 복원.
- 임계값 변경은 미완료 회복 확인을 취소하고 새 T로 평가. 이미 발송한 부족 구간 이력을 초기화하지 않음.
- Bluetooth가 끊겨도 차량 조회 결과를 실시간 확인한 것처럼 사용하지 않습니다. 지연·중복 메시지는 재전송 이력으로 구분.
- 화면의 남은 숫자·같은 메시지 반복·같은 requestId 응답 재처리는 횟수에 포함하지 않음.
- 회복 검증할 때만 필요한 추가 조회. 회복 완료·실패·단절·취소 후 예약 조회를 종료하고 무한 주기 조회 금지.
- 현재 API의 전 항목 refresh를3회 반복하지 말고 지원·권한 확인 후 연료 항목에 한정하는 방향으로 구현. 특권 권한 우회 금지.
- 한 세션에서 이전 콜백이 늦게 도착해 새 확인을 완료하지 않도록 세션ID·요청ID 사용.

조회 응답시간·요청 취소는 기존 SDK 어댑터의 제한과 대조합니다. 실제 고정 갱신 주기를 가정해 자동 성공 처리하지 않습니다.

## 6. 예시: 사용자20%

| 입력·상황 | 결과 |
|---|---|
| 연료18%, SOC80%, LOW_FUEL=OFF | 주유 필요, 최초/재무장 상태이면 알림1회 |
| 연료25%, LOW_FUEL=ON | 주유 필요 아님. 차량 경고로 우회 알림/노란색 생성 금지 |
| 연료 없음, LOW_FUEL=ON | 숫자 공란·새 주유 알림 없음 |
| 연료19%→21% | 캐릭터 주유 필요 해제. 재알림 준비는 아직 안 됨 |
| 별도 조회30%, 응답 후30초 이상 뒤31%, 다시30초 이상 뒤30% | 재알림 준비 완료 |
| 위 확인 중29% 수신 | 확인 취소 |
| 위 확인 중오류·단절 | 확인 중단 |
| 준비 완료 후20% | 새 주유 알림1회 |
| 여러 번 같은 메시지 전송 | 알림·회복 횟수 중복 없음 |
| HEV 연료80%, SOC10% | SOC 이유의 주유/충전 알림·노란색 없음 |

## 7. 친구 PC 적용 위치와 차이

최신 저장소(`90cf848`)는 차량`:app`, 휴대폰`:phone` 구조입니다. 예전 문서의 `mobile-app/` 경로는 당시 코드 설명이며 현재 작업에는 최신 구조를 사용하십시오.

| 현재 파일 | 구현 시 확인할 사항 |
|---|---|
| `app/.../CareCondition.kt` | 현재 HEV SOC도 energy에 포함하고 LOW_FUEL로 true가 될 수 있음. 새 기준과 충돌하므로 향후 구현 때 수정 |
| `app/.../vehicle/PleosVehicleGateway.kt` | 정수 잔량 수신·구독 경로. 기존 전체refresh와 회복용 연료 조회 구별 |
| `companion/.../BannerNotifications.kt` | 퍼센트 미수신 시LOW_FUEL 대체 경로·HEV 에너지 선택 확인. 새 기준으로 알림 연결 |
| `phone/.../MainActivity.kt` | 설정·차량 프로필·UI·동기화. HEV 설정명은 주유 알림 기준, EV는 충전 알림 기준 |
| `phone/.../PhoneLauncher.kt`, 차량캐릭터·미러·배너 정책 | 기존lowFuel 결과를 신뢰하는 경로 모두 동일한 잔량 기준 사용 |
| `app/.../VehicleCatalog.kt` 및 휴대폰 차량 선택 자료 | PHEV·수소차 선택 제외. 기존 기록은 보존·자동HEV변환 금지 |

정확한 전체 경로·역할은 친구 작업 시 최신 코드에서 재확인하십시오. 이 문서 작성은 기존 동작을 변경한 것이 아닙니다. 정비·세차·최근에 변경된 세차 완료 배너 정책은 덮어쓰지 않습니다.

## 8. 시뮬레이션·실수신 체크리스트

- [ ] 정수0/20/21/100 전달·표시 동일, null/-1/101/오류는 유효값으로 쓰지 않음.
- [ ] HEV 연료80/SOC10에서 에너지 알림·노란색 없음.
- [ ] 연료25/차량부족ON에서 사용자기준20에 따른 알림·주유캐릭터 없음.
- [ ] 연료미수신/차량부족ON에서도 대체알림 없음.
- [ ] 설정이하 최초연결·지속·설정변경·재연결·재시작의 중복 방지.
- [ ] 회복 별도조회3회, 응답간격>=30초·전체>=60초. 빠른3응답으로 완료 금지.
- [ ] 30→31→30 성공, 중간29 취소, 오류·단절 중단, 이전세션 지연 응답 제외.
- [ ] 같은SDK응답/같은Bluetooth메시지3번으로 완료되지 않음.
- [ ] 재무장완료 상태 복원, 미완료횟수 초기화, 임계값변경 재평가.
- [ ] 재알림 대기 중21%에서 캐릭터는 이미 주유필요 해제.
- [ ] 알림 끔·OS권한 거부와 실제 발송상태 처리.
- [ ] PHEV·수소차 선택 제외, 기존 기록 보존.
- [ ] 실제SDK의 getter·구독 콜백·단위·타임아웃을 확인하고 시험공급자 성공과 분리.

Bluetooth 물리 장치 테스트의 추가 사례는 [기존 일괄 목록](BLUETOOTH_VALIDATION_CHECKLIST.md)에 기록합니다. 에뮬레이터·주입 메시지로 실제 무선 검증 성공을 주장하지 않습니다.

# 추가 코드 최적화 검토

다중 차량·선택 번호판·기록 삭제·화면 밖 수신을 추가한 작업 트리에서 반복 작업을 줄였다. 기존 수정 사항은 보존했고, SDK·AVD 사양·Gradle 작업자 수·정비 완료 기준·HEV 정책은 변경하지 않았다.

## 변경

- `VehicleIconMonitor`: 저장 알림을 받은 뒤 실제 수신 차량 자료와 아이콘 설정이 달라진 경우에만 수신 처리 흐름을 다시 구성한다. 조회 차량 선택만 바뀌거나 같은 자료가 두 저장 키로 통지되는 경우 기존 관찰자를 유지한다. 수신 OFF와 수신 대상 변경은 계속 반영한다.
- 같은 서비스에서 주행 거리만 추가될 때는 휴대폰 확정 프로필/기록을 차량 저장 자료와 다시 대조하지 않는다. 확정 상태 또는 미전송 편집 대기 상태가 바뀌면 다시 대조한다.
- `rememberMaintenanceConfig`: 저장 알림마다 별도 코루틴을 늘리는 대신 변경 알림을 합치고 최신 읽기만 반영한다. 이전 읽기가 늦게 끝나 최신 상태를 덮는 것도 방지한다. 화면이 사라지면 관찰자를 해제한다.
- `CareJournal.outgoingState`: 구간·편집 요청·취소/삭제 목록을 같은 JSON 읽기에서 구성한다. 차량 전송 준비의 해당 저장 자료 해석은 3회에서 1회로 줄었다. 요청 기준 버전도 이미 읽은 자료를 재사용한다.
- 취소/삭제 목록이 비어 있으면 관련 JSON 해석·변경 저장을 생략한다.
- `CareAuthority`의 삭제/취소 이력 대조를 ID·방문별 인덱스로 처리한다. 기존의 이력 수×새 기록 수 중첩 탐색을 없애되, 중복 기록 모두에 취소를 적용하고 빠진 이력도 복원한다. 보호할 이력이 없으면 인덱스를 만들지 않는다.
- 차량 저장 및 휴대폰 확정 자료 반영에서도 삭제 ID 집합을 사용해 반복 전체 탐색을 줄였다.

이는 코드 경로와 작업 횟수를 확인한 결과다. 실차 CPU·배터리·화면 프레임 성능을 수치로 측정했다는 의미는 아니다. 새 의존성·폴링·캐시 파일·상시 인덱싱은 추가하지 않았다.

## 검증

- 양쪽 앱 JVM **63개 통과**(차량33, 휴대폰30). 1,500개 이력과 누락/중복 기록을 포함한 삭제 보호 회귀 검사를 추가했다.
- 차량/휴대폰 debug 및 검증 APK 빌드 성공, 양쪽 lint 오류0개. 최종 로그: `build/diagnostics/banner/optimization-final-build.log`.
- 구간 ACK 후에도 편집 요청과 취소/삭제 목록이 유지되는 Android 회귀 검사를 추가했다. 실물 Bluetooth 검증과는 별개다.
- 휴대폰 검증 APK의 `CareFlowTest` **14개 통과**,13.538초(`optimization-protocol-tests.log`). 단일 Pleos API34 AVD에서 프로토콜·저장·로컬 알림 로직을 검증한 것으로 휴대폰 화면/실물 무선 검사를 대신하지 않는다.
- Pleos 차량 저장·다중 차량 UI **10개 통과**(`optimization-native-tests.log`), 실제 SDK 재수신과 아이콘 전환 **2개 통과**(`optimization-background-sequenced.log`,40.77초). 이번 고유 Android 검사 수는 **26개**다.
- 최초 연속 실행은 아이콘 검사의 내비게이션 화면 전환 조건에서 실패했다(12개 중1개). 해당 검사 단독 실행은 통과했지만 두 검사 연속 실행에서 재현됐다. 앞 검사가 화면 복원을 요청만 하고 끝나 다음 검사와 시작 요청이 겹칠 수 있어, 복원 완료/메인 큐 처리를 기다리고 이미 열린 화면을 불필요하게 다시 시작하지 않도록 테스트 순서를 보완했다. 이후 두 검사를 함께 실행해 통과했다. 실패 로그도 삭제하지 않았다.
- 실제 차량 앱을 복원하고 `optimization-native-before.xml`/`optimization-native-after.xml`의 차량 저장 JSON을 비교해 원래 프로필·기록이 보존되었음을 확인했다. 화면 밖 수신 검사는 실제 Pleos SOC를 사용하며, 아이콘 색상 전환은 기존 시험 공급자 입력을 사용한 뒤 해제한다.

실제 무선 검사는 [통합 점검 목록](BLUETOOTH_VALIDATION_CHECKLIST.md)에 남겨둔다. 로컬 테스트 로그·자료 백업은 Git에 추가하지 않는다.

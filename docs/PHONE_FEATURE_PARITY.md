# 차량·휴대폰 기능 대조 및 한글 입력

2026-11-10 갱신: 아래 표는 이전 작업 기록이다. 세차 계산·휴대폰 최종 설정/기록·관리 알림의 현재 구현 범위와 실수신 제한은 [정비·세차 검증 결과](CARE_VALIDATION_RESULTS.md)를 따른다. 현재 휴대폰 관리 알림 코드는 연결됐지만 실제 Bluetooth 전송까지 검증한 상태는 아니다.

2026-11-09 차량 앱 소스와 휴대폰 앱을 대조했습니다.

## 블루투스 구현 상태

양쪽 앱의 보안 RFCOMM 서버/클라이언트와 권한·페어링 상대 선택, 데이터 검증·저장·단절 유지 코드는 구현되어 있습니다. 로직·저장 테스트도 통과했습니다. 따라서 단순한 연결 버튼만 만든 상태는 아닙니다.

다만 [Pleos 공식 문서](https://document.pleos.ai/en/docs/connect/guide/getting-started/application-development/configure-pleos-connect-emulator)는 현재 에뮬레이터의 Bluetooth 동글 연동을 지원하지 않는다고 설명합니다. 실물 Pleos 차량이 일반 앱에 이 RFCOMM 서비스를 허용하는지와 실물 두 기기 통신은 아직 미검증입니다. ‘에뮬레이터에서만 안 되고 실차에서는 확실히 된다’고 확정할 수는 없습니다. 연결 방법은 [동기화 문서](PHONE_COMPANION_SYNC.md)를 참고하세요.

## 입력창 수정

기록·차량 정보·닉네임 입력창은 시스템 영역과 IME 인셋을 반영하는 공통 Dialog를 사용합니다. 입력 영역만 스크롤하고 제목·키보드 닫기·취소·저장은 키보드 위에 유지합니다. 메모의 IME 완료와 명시적인 키보드 닫기 모두 초안 내용을 유지한 채 포커스를 해제합니다. 구현은 Android 공식 [DialogProperties](https://developer.android.com/reference/kotlin/androidx/compose/ui/window/DialogProperties) 및 [IME 인셋](https://developer.android.com/develop/ui/compose/system/insets-ui) 문서를 따릅니다.

## 개발 에뮬레이터 한글 입력기

기본 AOSP LatinIME에는 한글 조합 입력이 없어 휴대폰 AVD에 [Fcitx5 Android 0.1.3 공식 배포](https://github.com/fcitx5-android/fcitx5-android/releases/tag/0.1.3)의 x86_64 본체와 Hangul 플러그인을 설치했습니다. 공식 릴리스 SHA-256과 대조했으며 앱 런타임 의존성으로 넣지 않았습니다. 실제 휴대폰에서는 자체 한글 입력기를 그대로 사용합니다.

- IME: `org.fcitx.fcitx5.android/.input.FcitxInputMethodService`
- 본체 SHA-256: `aaeb569fc3e9e8ec532b0ea33be39ce77b143c8add824d172f17356ddc3b9ed2`
- Hangul SHA-256: `d8e8facd48fd6898e3f0b81723b38a25e94eb8667926ca61f2171ea253460a1b`
- Input Methods에 English와 Hangul을 등록했습니다. 하단 지구본으로 전환합니다. Hangul에서도 키 표시는 영문이지만 두벌식으로 조합됩니다.
- 물리 키보드가 있어도 화면 키보드를 표시하도록 Android 설정을 켰습니다. 시험한 AVD 키보드 플래그는 원래 값으로 복원했으며 RAM 2048 MB·1080×2400 해상도와 Pleos AVD는 유지했습니다.
- 시험 설치한 ReteKey는 물리 키보드 환경에서 화면 키보드를 숨기는 정책 때문에 제거했습니다.
- 실제 메모에 ‘한글’을 터치 입력하고 키보드 위 저장 버튼을 확인했습니다. 시험 초안은 저장하지 않았습니다.

기기 테스트는 전용 `.verification` 앱 ID에서 실행하며, 기본 휴대폰 데이터는 테스트 전후 별도 대조합니다.

# 코드 검토 후 반영 범위와 친구 작업 구분

2026-11-12 사용자 지시 기준. 기존 세차·정비 전체 정책은 관련 인계 문서를 유지한다.

| 항목 | 이번 변경 |
|---|---|
| 1. 하이브리드 주유 판단 | 일반 HEV는 연료 퍼센트만 사용. SOC와 차량 LOW_FUEL 플래그로 주유 알림/캐릭터를 켜지 않음. 차량·휴대폰·런처 동일 기준. EV는 SOC 사용 유지. |
| 2. 주유 재알림 회복 | **친구 담당. 이번 변경에서 제외.** T+10%p, 응답 후 30초 이상 간격의 별도 SDK 조회 3회 기준을 이번 코드가 구현했다고 해석하지 말 것. 작업 중 추가한 조회·회복 상태·전송 필드는 모두 제거함. 기존 재알림 동작은 유지. |
| 3. 정비 알림 범위 | 현재 직접 지원하는 ENGINE_OIL/BRAKE_FLUID/TRANSMISSION_OIL/WASHER 및 기존 집계 차량 경고만 유지. 준비된 이미지나 외부 eligible=true만으로 ABS 등 다른 원본 경고를 활성화하지 않음. 엔진오일 압력은 기존 집계 경고 경로 유지. |
| 4. 세차 반영 도중 종료 | 이번에 추가 복구 개발하지 않음. 사용자가 누락을 발견하면 관리 기록에 세차를 수동 추가. 자동 누락을 수동 입력이 보장해서 해결하는 것은 아니므로 잔여 제한으로 남김. |
| 5. 장기 방문 증거 보관/재전송 보강 | 사용자 요청으로 이번 범위에서 보류. |
| 6. 세차 날짜·완료 시각 수정 | 마지막 관리 날짜를 바꾸면 기존 자동 감지 완료 시각을 제거하고 Manual/UserRecord로 변경. 기존 기록 ID·메모·방문 ID를 유지하여 취소/중복 보호를 잃지 않음. 두 앱의 관리 기록 편집에서 세차 완료 시각을 HH:mm으로 선택 입력할 수 있음. |
| 7. 위치/블루투스 재연결 | 아래 재시도 정책 적용. 실제 무선과 차량 SDK 복구 결과는 별도 검증. |

## 세차 시각 입력

- 마지막 세차 날짜만 수정한 경우: 원래 자동 감지 시각을 재사용하지 않고 다음 날 00:00(한국 시간)부터 차감.
- 관리 기록에서 시각을 직접 입력한 경우: 선택한 날짜와 한국 시간 HH:mm을 UTC Instant로 저장하여 해당 완료 시각 이후 이력 계산에 사용.
- 시각을 비워두면 날짜만 저장. 유효하지 않은 시각/미래 시각 저장 불가.
- 자동 기록의 제목·메모만 수정하면 원래 감지 시각 유지. ‘수동 기록으로 전환’을 선택하면 원래 시각을 지우고 사용자가 새 시각을 입력하도록 함.
- 수동 전환은 기존 방문을 삭제하거나 새 방문을 생성하는 동작이 아님. 같은 ID와 방문 연결 유지.

## 재연결

위치:

- 일시적인 Error/Disconnected/NoData 수신 시 기존 위치 SDK 구독을 종료한 뒤 **1초 → 3초 → 10초**, 최대 3회 재시도.
- 권한 거부·기능 미지원·위치 차단은 자동 반복하지 않고 설정 확인 안내. 화면의 새로고침으로 명시적 재연결 가능.
- 이전보다 새로운 측정 시각의 유효한 위치 수신 시 재시도 예산 초기화. 같은 캐시 위치 재수신만으로 초기화하지 않음. 소유 화면/서비스가 모두 수집을 해제하면 예약 재시도도 취소.
- 위치 SDK가 오류 콜백 없이 조용히 중단되는 경우를 자동 탐지하는 별도 watchdog은 추가하지 않음. 고정 수신 주기나 시동 종료 후 지속 수신은 보장하지 않음.

블루투스:

- 휴대폰 클라이언트의 최초 연결/수신 실패 후 **1초 → 3초 → 10초**, 최대 3회 재시도(최초 포함 최대 4회 연결 시도).
- 각 시도는 기존 15초 연결/첫 프레임 제한 유지. 총 대기 시간은 SDK/OS 스케줄링에 따라 달라짐.
- 유효한 앱 프레임을 받으면 새 실패에 대한 재시도 예산 초기화. 단순 소켓 연결 성공만으로 초기화하지 않음.
- 3회 실패 시 서비스 상태와 기기 연결 화면에 수동 연결 안내. 해당 서비스 알림을 누르면 앱으로 이동 가능.
- 블루투스 OFF·권한 없음에서는 시도 중단. 블루투스 ON 이벤트에서 선택된 페어링 기기로 다시 연결. 사용자가 서비스 종료/기기 변경하면 기존 예약·소켓 종료.
- 차량 서버는 기존처럼 선택한 페어링 기기의 접속을 기다리는 방식 유지. 무한 클라이언트 재접속/새 기기 탐색은 추가하지 않음.

## 검증 구분

- 단위 테스트: HEV 연료만 판단, LOW_FUEL 무시, 지원 정비 목록 제한, 수동 날짜 수정 시 ID 유지·자동 시각 제거, HH:mm 검증, 재시도 예산.
- 에뮬레이터 검증은 실제 차량 센서·물리 Bluetooth 송수신 검증과 다름. 실제 무선 실패/복구 체크는 `BLUETOOTH_VALIDATION_CHECKLIST.md`의 BT-53에서 일괄 진행.
- 2번 친구 작업 기준은 `HEV_FUEL_ALERT_POLICY.md`를 참고하되 그 문서의 1번 판단 부분은 이번에 코드 반영되었고, 회복 기준 구현은 별도라는 점에 주의.

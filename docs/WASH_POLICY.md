# 세차 점수·자동 감지 정책

2026-11-10 사용자 재확인: **아래 시설별 조건을 충족하면 우선 세차로 반영한다. 전용 셀프 세차장이나 주유 구역과 명확히 분리된 세차 구역이 확인되면 ‘세차 완료!’, 장소 구분이 애매하면 ‘세차한 것 같아!’ 확인 배너를 보낸다. ‘세차 안 했어요’를 누르면 해당 방문을 취소하고 이전 기준으로 재계산한다.** 실제 물세차 여부의 애매함은 추가 보류 조건이 아니다. 정차식/P 기반 시설에 N단 조건을 강제하지 않는다. 신호·체류·세차 구역 등 필수 조건 자체가 빠진 경우와 구별한다. 시설 입장만으로 완료 처리하지 않는다.

상태: 사용자 합의 기준 및 최신 세부 처리안 반영. 일부 센서 임계값은 초기 시험값이며 수신 데이터로 검증 후 확정 필요. 구현 완료 문서가 아닙니다. [세부 처리·검증 상태](CARE_IMPLEMENTATION_DETAILS.md)를 함께 읽습니다.

## 1. 점수 의미와 시간

- 청결도는 실제 표면 오염 센서값이 아닌 **추정 관리 점수**. 내부 소수점, 표시 정수, 범위 0~100.
- 날짜 경계·하루 먼지 한도는 `Asia/Seoul`. 이벤트 시각은 시간대 변환 가능한 절대 시각으로 보존.
- 미래 세차 날짜는 허용하지 않으며 기존 사용자 기록을 보존.

## 2. 최초 기준·수동 관리기록

| 상황 | 정책 |
|---|---|
| 최초 마지막 세차일을 앎 | 해당 날짜 100% 기준. 그다음 날 00시부터 현재까지 계산 |
| 마지막 세차일 모름 | 점수 null, 숫자 공란. 퍼센트 알림 없음 |
| 수동 관리기록에 세차 추가 | 시각 입력 불필요. 해당 날짜 차감 없음, 다음 날 00시부터 계산 |
| 첫 자동 감지 | 추정 완료 시점 100% 기준으로 시작 |
| 과거 기록에 날짜만 존재 | 새 수동 기록과 동일하게 다음 날 00시 적용. 임의의 실제 세차 시각 생성 금지 |

수동 기록을 오늘 추가하면 오늘은 100%입니다. 과거 기록이면 다음 날부터 확보된 실제 데이터 또는 평균 거리로 재계산합니다. 자동 감지는 감지 완료 시각 이후 차감을 적용합니다. 이 둘은 합의된 의도적인 차이입니다.

집·출장 세차는 자동 감지만 제외합니다. **기존 관리기록으로 수동 반영 가능**하며 별도 완료 버튼은 새로 만들지 않습니다. 이전 대화의 수동 반영 전면 제외·수동 시각 필수 정책은 폐기합니다.

## 3. 시간 구간별 거리 산정

1. 유효한 실제 거리 확보 구간: 실제 km.
2. 실제 정차·미주행이 확인된 구간: 0km. 데이터가 없다는 사실만으로 0km로 판단 금지.
3. 나머지 미확인 구간: **20km × 구간 초 / 86400**.
4. 실제 데이터가 나중에 들어오면 같은 구간의 평균 추정치를 대체. 두 값을 더하지 않음.

SDK가 관측 사이 누적거리 차이를 제공하면 그 차이가 덮는 구간에 평균 거리를 중복 적용하지 않습니다. 긴 구간 총거리만 아는 경우 구간 내부의 날씨별 이동 분포를 임의 생성하지 않습니다.

거리 감소·단위 미확인·차량 변경·비정상 급증은 유효한 실제 거리로 인정하지 않습니다. 사용할 수 없는 구간은 미확인으로 분류해 평균 정책을 적용하고 내부 사유를 보존합니다. 장시간 미수신을 주차로 가정하지 않습니다.

사용자 화면에는 별도 '일부 이력 누락' 안내를 강제하지 않습니다. 다만 내부에서 실제·평균·미수신과 계산 출처는 구별합니다. 실제 데이터 보정으로 점수가 올라가도 세차 완료 이벤트를 만들지 않습니다.

## 4. 차감 계수

다음은 합의한 **앱 초기 운영 계수**이며 제조사 공식 오염률·실측 검증값이 아닙니다. 기존 코드 계수 대신 단일 정책으로 사용합니다.

| 항목 | 차감 |
|---|---:|
| 기본 거리 | 0.10%p/km |
| 우천 추가 | 0.20%p/km |
| 강설 추가 | 0.40%p/km |
| PM10 >80 또는 PM2.5 >35 | 0.03%p/km 추가 |
| PM10 >150 또는 PM2.5 >75 | 0.06%p/km 추가 |

- PM 단위 µg/m³. 높은 단계 하나만 적용. PM10·PM2.5 합산 금지.
- 비·눈 중복은 눈 추가분 하나. 비·눈 추가 적용 구간은 먼지 추가분 제외.
- 먼지 추가분만 차량별 한국 날짜 하루 최대 2%p. 기본·강수 차감은 이 한도 대상 아님.
- `dust`는 참고 보관만. 별도 차감하지 않음.
- 평균 거리 20km/일의 기본 차감은 2%p/일. **별도 날짜 차감 없음**.
- 0~100으로 최종 제한. 구간별 정수 반올림하지 않음.

## 5. 날씨 매칭

- **실제 이동의 시각·위치가 확보된 구간만** 날씨 추가 차감 대상.
- 평균 거리 구간이나 주행 분포를 모르는 총거리 구간에는 기본 차감만 적용.
- 주차 중 비·눈·먼지는 차감하지 않음.
- Open-Meteo 시간별 `snowfall >= 0.1cm`이면 눈, 그렇지 않고 `rain + showers >= 0.1mm`이면 비.
- 모델값을 차량 물 노출 실측이나 도로 적설·제설제 확인으로 표현하지 않음.
- 시간별 강수는 API의 직전 시간 집계 정의에 맞춰 매칭. 일일 강수량·확률로 전일 차감 금지.
- 구간을 시간대·공간에 맞춰 분할하되 데이터가 입증하지 않는 분 단위 강수 시작 시각은 생성하지 않음.
- 날씨 누락은 기본 차감 먼저 반영. **주행 구간 종료 후 72시간 이내** 확보된 대응 자료로 추가 보정, 이후 자동 소급 보정 마감.
- 구간 ID·자료 버전·적용 내역으로 재조회 중복 차감 방지. 과거 날씨의 제공 범위·자료 종류는 공급자 문서 확인.

## 6. 자동 감지 상태 흐름

`시설 진입 → 구별 가능한 세차 구역 진입 → 유효한 체류 180초 이상 → 유형별 차량 패턴 → 구역 이탈·시설 출차 → 자동 추정`

| 시설 | 필수 근거 |
|---|---|
| 컨베이어식 | N + 오차로 설명하기 어려운 실제 이동, 이후 D 전환·출차 |
| 정차식 | 구별 가능한 세차 구역 내 정차 체류, 이후 차량 출차 |
| 주유소 복합 | 주유·세차 영역을 구별할 수 있어야 함 |
| 장소 경계·방식 미확인 | 판정 보류. 지도 점 좌표를 실제 세차기 경계로 간주하지 않음 |

주유소 전체 체류·P/N·연료 증가만으로 초기화 금지. GPS 흔들림은 컨베이어 이동 근거가 아닙니다. 속도·누적거리가 컨베이어 이동을 반드시 검출한다고 가정하지 않습니다. 와이퍼는 필수 조건 제외, 고압수 센서로 해석 금지. 같은 방문은 한 번만 처리합니다.

**180초 정의:** 컨베이어식은 세차 구역 안에서 유효하게 확인된 체류이며 컨베이어 이동 시간을 포함합니다. 정차식은 같은 구역에서 정차가 확인된 체류입니다. 둘 다 구역 밖 주유·대기는 제외합니다. 기어 P/N만으로 정차를 단정하지 않습니다.

**초기 시험 프로필:** 구역 근처 위치 요청5초, 위치 생성 후10초 이내·수평 정확도10m 이하, 내부 연속10초로 진입, 공백15초 이하 후보 유지(공백은 체류 미포함), 구역 밖 유효 위치30초 및 실제 이동으로 출차 확인. 상세 조건은 [세부 처리안](CARE_IMPLEMENTATION_DETAILS.md)에 있습니다. 이는 검증 완료 기준이 아닙니다. 실제 수신 간격·정확도·지도 구역으로 검증하고 설정 버전과 결과를 보존합니다. 과거의 고정 출차20m 제안은 필수값으로 사용하지 않습니다. 컨베이어 이동의 최소 근거는 별도 검증하며 지원 불가이면 자동 판정을 보류합니다.

## 7. 시동 종료·휴대폰 위치 보완

- 차량 위치·기어 신호 우선. 차량 데이터 중단 전 구역 진입 근거가 있어야 함.
- 이후 유효한 휴대폰 위치로 같은 구역의 체류를 보조 확인. 실제 확인된 시간만 누적.
- 휴대폰은 사람과 이동하므로 휴대폰 체류만으로 초기화 금지.
- Bluetooth 단절을 시동 OFF·세차로 간주하지 않음. 시동 OFF와 SDK 종료가 항상 동일하다고 가정하지 않음.
- 차량 재연결 후 차량 위치·출차 및 앞뒤 근거의 일관성 확인.
- 양쪽 모두 공백이면 임의로 180초를 채우지 않고 판정 보류.
- 휴대폰 위치 권한·백그라운드 동작 미지원 시 근거 부족 방문은 자동 감지하지 않음. 기존 관리기록 수동 반영 가능.

이 절은 이전의 '휴대폰 위치 보완 제외' 제안을 대체합니다. 180초는 세차 완료를 증명하지 않으므로 결과는 항상 자동 추정입니다.

## 8. 기록·초기화·취소

- 자동은 추정 완료 시점 100%. 지연 수신은 이후 구간 차감을 적용한 현재 점수 표시.
- 구분이 애매한 적격 방문은 알림/앱 배너 제목 `세차한 것 같아!`, 본문은 세차로 먼저 반영했으며 주유만 했거나 세차하지 않았다면 알려 달라는 안내.
- 전용 셀프 세차장/주유 구역과 분리된 세차 구역이 검증된 적격 방문은 `ClearFacilityPattern`을 보존하고 `세차 완료!` 알림. 확인 질문은 띄우지 않는다. 이것도 시설·행동 기반 추정이며 SDK 물세차 완료 신호가 아니다. 가까운 POI나 시설 이름만으로 이 등급을 부여하지 않는다.
- 액션 `[세차 안 했어요] [기록 보기]`. 앱 배너의 `[닫기]`와 응답 없음은 자동 반영 유지. ‘세차 안 했어요’는 해당 visitId 취소이며 같은 방문 재전송으로 부활하지 않음.
- 자동 추정 반영 후 7일 동안 취소 가능. 취소 방문 ID는 재수신으로 부활하지 않게 유지.
- 원본 상세 위치는 기본30일 후 삭제. 재계산용 비위치 구간 장부·기준·기록은 차량 관리기록과 함께 유지하며 30일 만료로 삭제하지 않음. 보관 상세는 세부 처리안 참조.
- 수정·삭제·취소는 최근 유효한 세차 기준으로 재계산. 이전 기준도 없으면 null.
- 자동 추정은 visitId와 연결된 기존 관리기록 한 건으로 저장. 비용·메모 보완은 같은 기록 편집. 같은 날짜 수동 추가 시 기존 자동 기록 보완/별도 세차 선택 제공, 날짜만으로 자동 병합 금지. 단순 메모 수정은 자동 시각 유지, 명시적으로 수동 기록으로 전환하면 다음 날00시 기준으로 재계산.
- 완료 기준 시각을 걸치는 거리 구간은 분리 근거가 있는 부분만 반영, 임의 배분 금지.

## 9. 알림

- 기존 `CarProfile.washAlert`: 기본 30%, 현재 UI 범위 5~50%, 5 단위. **사용자 설정 재사용**.
- 고정 30%·10% 이중 알림 제안은 폐기. `notifications` 및 OS 권한 준수.
- 양수 값은 일반 반올림(0.5 올림)한 표시 점수와 동일한 값으로 임계값 비교.
- null은 알림 없음. 임계값 이하일 때 세차 주기당 필요 알림 한 번.
- 설정 변경·알림 재활성화 시 현재 상태 평가, 같은 주기 중복 발송 방지.
- 보정·기록 취소·앱 재시작·재연결로 과거 알림 반복 금지.
- 새 유효 세차 주기에 다시 알림 가능. 세차 감지 알림은 필요 알림과 별도 이벤트.

## 10. 계산 예시

한국 시간 11월 1일 수동 세차 → 11월 2일 00시부터 계산. 실제 데이터 없이 11월 9일 00시라면 7일 ×20km=140km →14%p 차감 →86%.

실제 30km 중 비 구간 10km라면 기본3%p+우천2%p=5%p 차감. 평균 거리 구간에 그날 비 예보만으로 추가 차감하지 않음.

첫 세차일 모름 → null. 이후 자동 추정 첫 세차 → 완료 시점100%. 그 기록 취소 후 다른 기준 없음 → null.

## 1. 화면 작업 시 사용할 조회 진입점

호출 예시(좌표는 호출자가 권한·유효성을 확인해 전달; 하드코딩 시연 위치를 실차 위치로 쓰지 않음):

```kotlin
val forecast = WeeklyWeatherRepository().fetch(latitude, longitude)
// forecast.days: 7개. 날짜와 각 nullable 필드를 읽는다.
// forecast.fetchedAt: 앱이 응답을 받은 시각. 모델 생성 시각/관측 시각이 아님.
```

앱 수명주기에 맞는 코루틴에서 호출하고 예외와 취소를 처리한다. Compose 재구성마다 직접 호출하지 않는다. 새 의존성·폴링·캐시 정책을 추가하지 않았다. 양쪽 앱이 같은 지점의 자료를 중복 조회할 필요는 없다. 주행 날씨는 휴대폰 조회를 기본 방향으로 한다.

요청: `https://api.open-meteo.com/v1/forecast`에 `forecast_days=7`, `timezone=Asia/Seoul`, `daily=weather_code,temperature_2m_min,temperature_2m_max,precipitation_probability_max,precipitation_sum,snowfall_sum`, 섭씨/mm 단위 명시. 날짜는 API 반환값으로 읽으며 한국 자정 경계에 이전 날짜 응답이 오면 실패로 처리하고 다음 호출에서 재시도한다. 자동 재시도/화면 갱신 시점은 이번에 정하지 않는다.

`weather_code`는 그날 가장 심한 날씨를 나타내므로 하루 종일 그 상태라는 뜻이 아니다. 최대 강수확률은 시간별 확률의 최댓값이다. 총강수량은 눈의 물 환산량도 포함하므로 강설량(cm)을 그대로 더하지 않는다. 현재 화면용 예보를 과거 주행 점수에 연결하지 않는다.

## 2. 주행 구간 생성: 합의한 단순 방식(친구 구현 대상)

1. 차량별/수집 세션별 최초 유효 누적거리와 수신 시각을 기준점으로 저장한다. 거리 단위는 확인된 km로 통일한다.
2. 같은 누적거리 값이 반복되면 차감하지 않고 기준점을 뒤로 옮기지 않는다. **정차로 확정하지 않는다.** 위치는 별도로 갱신한다.
3. 증가 시 기준점부터 현재까지 한 구간을 만들고 증가분을 실제 거리로 반영한다. 현재 값을 다음 기준점으로 한다.
4. `10,000 → 10,000 → 10,001km`는 총 1km, 기본 0.1%p 차감. 미터 단위 경로 복원/속도 적분은 요구하지 않는다.
5. 정상 수신·거리 증가 / 정상 수신·거리 동일 / 수신 이력 없음 을 구분한다. 예전 SDK 값을 BT로 재전송한 것은 새 수신으로 세지 않는다. 동일 거리도 서로 다른 정상 SDK 응답이면 새 수신으로 인정할 수 있다.
6. 하루 20km 평균은 실제 거리 이력이 없는 시간에만 시간 비례 적용한다. 동일 거리 반복에 평균 차감을 더하지 않는다. 이후 같은 구간의 실제 증가분으로 보완한다면 해당 평균분을 대체하며 더하지 않는다.
7. 음수 거리, 비정상 증가, 단위 미확인, 재시작/수신 차량 변경/단절은 구간을 강제로 이어 붙이지 않는다. 마지막 유효 SDK 수신 이후 미확인 시간은 평균 보완 대상이며 마지막 값이 계속 수신되는 것으로 취급하지 않는다.
8. 기본 거리 차감과 날씨 연결 적격 여부는 별개다. 날씨 조건 미달로 정상 거리 증가분까지 버리지 않는다. 누적거리 동일만으로 ‘실제 정차’ 근거가 필요한 세차장 감지에 사용하지 않는다.

보관/전달 항목: 차량 ID, 세션 ID, 구간 ID, 시작/종료 시각(UTC Instant), 시작/종료 누적거리, 증가 거리(km), 시작/종료 유효 위치와 각각의 수신 시각, 대표 위치, 실제/시험 출처, 날씨 연결 가능 여부/내부 보류 사유. 원시 좌표를 로그·Git에 올리지 않는다.

## 3. 주행 날씨 연결 적격 기준

아래 수치는 **합의한 초기 시험값**이며 SDK/기상기관 정확도 보장이 아니다.

| 항목 | 처리 |
|---|---|
| 시간 | 증가가 확인된 구간이 5분 이내 |
| 위치 시각 | 시작/종료 시점 각각 기준으로 직전 60초 이내 수신된 유효 위치. 미래 시각/오류/미수신 제외 |
| 위치 간격 | 시작~종료 직선거리 5km 이내. 이를 실제 주행거리로 대체하지 않음 |
| 대표 위치 | 위 조건 충족 시 종료 위치 |
| 기상 시간대 | 동일한 시간별 강수 구간 안에 전부 포함. 경계 초과는 날씨 추가 차감 보류 |
| 비정상 위치 | 좌표 범위 밖/순서 역전/순간이동 등 명백한 오류는 제외. 5km 이내라고 모든 위치가 정확하다는 뜻은 아님 |
| 위치 정확도 | 이 날씨 연결 기준에 세차장 감지용 10m 정확도를 강제하지 않음. SDK confidence를 임의로 미터로 환산하지 않음 |
| 실패 | 실제 거리는 기본 차감. 날씨 추가 차감은 확인 가능한 항목만 적용 |

5분/5km가 같은 기상 격자임을 보장하지 않는다. 공모전용 대표 위치 추정 방식이다. 터널·국지 소나기·차량 표면 오염을 입증하지 않는다. 짧은 구간 실제 수신부터 검증한 뒤 확장한다.

## 4. 시간별 API와 시간 연결(아직 코드 없음)

- 날씨: `/v1/forecast`의 `hourly=rain,showers,snowfall`, 대기질: `https://air-quality-api.open-meteo.com/v1/air-quality`의 `hourly=pm10,pm2_5`를 조회한다. `dust`는 추가 차감에 쓰지 않는다.
- UTC로 보관하고 한국 시간/응답 timezone을 일관되게 해석한다. 비·소나기 mm, 눈 cm를 구분한다. 필요한 과거 범위만 조회한다. API 과거 자료도 모델 자료이며 실측으로 부르지 않는다.
- **강수:** API 15:00 값은 직전 14:00~15:00 합계. 14:10~14:12 구간은 이 값에 연결한다. 기존 `HourWeather.hourStart`에는 정규화된 구간 시작 14:00을 넣는다. 원 응답 시각을 그대로 시작 시각으로 넣으면 1시간 어긋난다.
- **PM:** 순간 시각 값이다. 초기 구현은 해당 시각의 값으로 다음 1시간을 대표하는 방식(14:00 PM → 14:00~15:00 주행)을 사용하고 모델 값 유지 추정임을 구분한다. 직전 1시간 강수와 같은 의미로 취급하지 않는다. PM이 누락돼도 비·눈 값이 있으면 그 보정은 가능하다.
- 구간 종료 이후 자료를 연결하고, 종료 후 72시간 이내 확보한 자료만 보완한다. 아직 끝나지 않은 시간대의 강수를 최종값처럼 먼저 차감하지 않고 필요한 응답을 나중에 확보한다. API 제공 지연으로 기한 내 확보하지 못하면 기본 거리 차감만 유지.
- 지역·시간별 응답은 재사용할 수 있지만 요청 지점/기상 시간/자료 출처를 포함해 구분한다. 같은 시간이라는 이유로 다른 지역 값을 공유하지 않는다. 격자 캐시 정밀도와 화면 갱신 주기는 이번 범위에서 추가 결정하지 않는다.

## 5. 차감 규칙: 기존 합의 유지

기본 = 실제 거리 또는 미확인 시간의 평균 거리 × 0.10%p/km. 둘을 같은 시간에 중복 적용하지 않는다. 별도의 날짜 경과 차감은 없다. 평균 거리에는 날씨 보정 없음. 주차 중 날씨 영향도 반영하지 않는다.

| 연결된 실제 주행 날씨 | 추가 차감 |
|---|---|
| 눈 snowfall ≥0.1cm | 0.40%p/km |
| 눈 조건 미달, rain+showers ≥0.1mm | 0.20%p/km |
| 강수 없음, PM10>150 또는 PM2.5>75 μg/m³ | 0.06%p/km |
| 강수 없음, 위 기준 미달이고 PM10>80 또는 PM2.5>35 | 0.03%p/km |
| 나머지 | 추가 없음 |

- 눈 우선, 비·눈 중복 없음. 강수가 있으면 먼지 추가 차감 없음. 눈이 0보다 크지만 0.1 미만인 구간도 ‘강수 없음’으로 바꿔 먼지를 더하지 않는다.
- PM10/PM2.5 중 더 높은 단계 한 번만, 한국 날짜 기준 먼지 추가 차감 최대 2%p/일. 먼지만 있고 강수 정보가 누락되면 강수 없음이 확인되지 않으므로 먼지 보정 보류.
- 점수는 0~100, 소수점 계산 유지 후 화면 표시만 기존 반올림. 구간 ID별 기본/날씨 추가분을 보관해 재수신·날씨 보완 때 추가분을 교체(누적 덧셈 금지). 정책 버전/기상 구간/조회 시각/출처를 내부 보관.
- 기존 최초 세차일/모름/null, 수동 날짜 다음 날부터 계산, 자동 세차 시점 초기화·취소 정책은 유지. 일부 누락 이력을 별도 경고로 사용자에게 표시하지 않는다.

## 6. 친구 구현 순서와 검증

1. 주간 예보: `WeeklyWeatherRepository.fetch` 호출 → 7일 날짜/단위/null/실패 확인 → 친구가 별도 화면에 연결. 추천 기능은 만들지 않음.
2. 차량에서 시각·거리·위치 수신 간격 확인. 기어는 별도 감지용이며 기본 거리 차감에 필수 아님. 속도 수집은 현재 코드에 없고 이번 문서만으로 추가되지 않는다.
3. 짧은 실제 거리 구간 생성 → BT 전달/중복 방지 → 휴대폰 시간별 날씨 연결 → 추가분 계산.
4. 시험: 동일 거리 반복, 1km 증가, 위치 없음/오래됨, 5분/5km 경계, 시간 경계, 강수 응답의 1시간 오프셋, PM 시각, 비·눈 중복, PM 일별 상한, 조회 실패·null·지연, 중복/역순 프레임, 차량 변경, 세차 기준 시점 전후를 확인.
5. 실제 API 조회와 데모 점수 계산을 분리해 시연. 데모 위치·비·눈은 명시적으로 시험 출처로 저장하고 실사용 기록/알림에 섞지 않는다. 발표 당일 비가 올 필요는 없다.
6. 실제 무선/SDK 실수신은 에뮬레이터 주입으로 입증하지 않는다. 무선 검사는 `BLUETOOTH_VALIDATION_CHECKLIST.md` BT-48에서 나중에 함께 수행.

## 3. 대상과 교체주기 선택

- 가솔린·디젤·엔진이 있는 일반 하이브리드는 대상입니다. BEV·FCEV는 대상이 아닙니다. 혼합 차종의 전기차 버전도 제외합니다.
- 제공 데이터에는 37개 차종 정책이 있고 엔진오일 대상은 29개입니다. 과거 모든 세대·연식의 공식 검증을 완료했다는 뜻은 아닙니다.
- 사용자 제공 `code_artifact.md`의 25차종 통합 표는 사용자의 명시적 선택으로 제품 기준에 채택했습니다. 셀토스·니로·레이는 기존 공식 자료, K4는 별도 해외 공식 자료를 보완했습니다.
- 항상 **가혹 조건의 반복 교체 주기**를 사용합니다. 최초/반복 교체 분기를 만들지 않는 선택이며, 최초 주기가 더 짧은 차량까지 항상 보수적이라는 보장은 아닙니다.
- 차종·연식·엔진·국가를 알면 해당 후보를 선택합니다. 엔진이 없으면 같은 차종·연식·국가에 해당하는 후보 중 짧은 주기를 선택합니다. 연식 등 정보가 없으면 데이터의 `conservativeModelReference`는 차종 단위 참고값으로 쓰되 정확한 공식 연식별 매칭이라고 표시하지 않습니다.
- 모든 차종을 하나의 5,000km 기준으로 통일하지 않습니다. 사용자 제공 엔진 유형별 후보는 자연흡기/자연흡기 HEV/승용 LPi 7,500km·6개월, 가솔린 터보/터보 HEV/N 5,000km·6개월, 명시된 포터·봉고 터보 LPi 7,500km·6개월, 디젤 10,000km·6개월입니다. 상세 차종 후보가 있으면 그 범위를 확인합니다.
- K4의 국가·엔진 미지정 앱 참고값은 확보 후보 중 5,000km·6개월입니다. 미국의 공식 8,000km·6개월 등을 한국·전 세계 공식 공통값으로 바꾸지 않습니다.
- 거리 또는 기간 중 먼저 도달하면 교체 시기입니다. 가혹 조건 자동 판정·날씨/정체에 따른 별도 추가 차감은 하지 않습니다.
- 선택한 주기와 데이터 버전은 차량별로 보관합니다. 화면·캐릭터·휴대폰 알림은 같은 계산 결과를 사용합니다.

## 4. 가입 시 마지막 교체 이력

최초 안내에서 정비 명세서·기존 정비 앱을 찾아보라고 요구하지 않습니다. 마지막 교체일은 날짜 입력 / 대략 기억함 / 모르겠음으로 처리합니다. 현재 누적거리는 정상 수신한 차량 값을 자동 사용하되 현재 거리와 과거 교체 당시 거리는 구분합니다.

| 입력 | 기준 교체일 | 교체 당시 실제 거리가 없을 때 |
|---|---|---|
| 정확한 날짜 | 입력 날짜 | 그날부터 가입일까지 20km/일 추정 |
| 약 1개월 전 | 가입일에서 1개월 전 | 같은 방식으로 추정 |
| 약 3개월 전 | 가입일에서 3개월 전 | 같은 방식으로 추정 |
| 6개월 이상 전 | 가입일에서 6개월 전 | 같은 방식으로 추정. 최소 6개월 경과라는 하한 정보 보존 |
| 모르겠음 | 기준일 없음 | 가입 전 거리를 만들지 않고 퍼센트 공란 |

“6개월 이상 전”에 6개월 전 날짜를 사용한 것은 실제 날짜의 확정이 아닙니다. 적용 기간이 6개월이면 즉시 기간 주기 도달로 처리합니다. 다른 적용 기간에서는 실제 사용 기간이 더 길 수 있다는 하한 정보가 사라지지 않게 합니다.

가입 전 실제 교체 당시 거리와 가입 시 실제 누적거리 모두 있다면 그 차이를 우선하고 같은 기간에 20km/일을 더하지 않습니다. 추정 날짜·거리는 실제 기록으로 위장하지 않고 계산 출처로 보관합니다. 교체 기준일이 미래이거나 차량 값이 오류인 경우 계산에 넣지 않습니다.

## 5. 거리·기간·잔여율 계산

### 5.1 가입 전 추정과 가입 후 실제 거리

```text
D = 기준 교체일과 가입일 사이의 경과 일수
가입 전 추정 관리거리 = D × 20km
교체 후 관리거리 = 가입 전 관리거리 + 가입 후 실제 누적거리 증가분
```

한국 현지 날짜 기준으로 두 날짜의 차이를 계산합니다. 가입 기준 날짜와 차량별 거리 앵커는 고정해 보관하며 앱을 다시 열었다고 가입일을 옮기지 않습니다. 평균 20km/일로 만든 값을 차량이 실제 제공한 과거 누적거리로 저장하지 않습니다.

가입 후 현재 누적거리가 정상 수신되면 증가분만 더합니다. 동일 값 반복은 증가분 0이며, 이것을 주차 확정이나 평균 거리 추가의 근거로 삼지 않습니다. 10,000→10,000→10,001km는 총 1km입니다.

수신이 끊겼다가 같은 차량의 유효 누적거리가 다시 들어오면 마지막 유효값과의 차이로 보완합니다. 그 공백에 평균 20km를 별도로 추가하지 않습니다. 누적거리 단위 확인, 음수·비정상 값·역전·다른 차량 혼입 배제는 필수입니다. 오류 상태를 0km로 바꾸지 않습니다. 거리 계산을 못 하는 동안 기간은 계산할 수 있지만 숫자·상태의 출처를 보존합니다.

### 5.2 계산식

```text
거리 사용률 = 교체 후 관리거리 / 적용 거리 주기
기간 만료일 = 기준 교체일에 적용 개월 수를 더한 날짜
기간 사용률 = 기준 교체일부터 경과한 기간 / 기준 교체일~기간 만료일의 전체 기간
잔여율 = 100 × (1 - max(거리 사용률, 기간 사용률))
표시 범위 = 0~100%
```

달력 개월을 모두 30일로 치환하지 않습니다. 월말 날짜는 달력의 월 더하기 규칙에 따라 처리하고 시간대는 Asia/Seoul로 일관되게 사용합니다. 내부 계산은 소수값을 유지하고 화면에 정수로 표시합니다. 주기 도달은 표시 반올림값이 아니라 실제 거리·기간 비교로 판단합니다. 기간 또는 거리가 도달하면 “교체 시기 도래”, 0% 이후에는 음수 대신 초과 거리·기간을 표시합니다.

평균 거리 또는 대략 날짜가 포함되면 “예상 잔여율”입니다. 실제 오일 성분·품질의 실측 수명이 아닙니다. 확정 교체일·거리도 물리적 오일 수명 측정값은 아닙니다.

### 5.3 마지막 교체일 자체가 없는 경우

- 교체 기준일을 가입일로 위장하거나 100%로 초기화하지 않습니다. “교체 이력 미등록”, 퍼센트 공란입니다.
- 가입 시각·최초 유효 차량 누적거리와 이후 실제 증가분을 별도로 저장합니다. 이 값은 설치 이후 주행이며 교체 이후 주행이라고 부르지 않습니다.
- 가입 이후 거리 또는 기간이 적용 주기에 도달하면 “설치 이후 ○km를 주행했어요. 그동안 교체하지 않았다면 교체 시기를 확인해 주세요”라고 안내합니다. 기간만 도달하면 경과 기간에 맞는 문구를 씁니다.
- 이 안내는 그때까지 교체를 기다려도 된다는 의미가 아닙니다. 가입 전 사용량을 모르는 상태입니다.
- 정비소 방문 후 확인 또는 직접 관리기록으로 첫 교체 기록이 생성되면 그 기록부터 100%로 출발합니다.

교체일은 모르지만 **교체 당시 실제 누적거리는 아는** 경우에는 그 실제 거리로 남은 km만 계산할 수 있습니다. 날짜나 기간 사용률을 만들지 않고 종합 퍼센트는 공란으로 둡니다. 반대로 확정 교체 후 날짜만 저장되고 당시 거리가 없으면 기간 안내만 가능합니다. 두 경우 모두 부분 정보와 교체 이력 완전 미등록을 내부에서 구분합니다.

## 6. 정비소 방문에서 교체 확인 질문까지

### 6.1 30분 체류 추정

```text
지도에서 확인한 정비소 안에 차량 위치 확인
    → 실제 차량 시동/전원 OFF 신호·시각·마지막 유효 차량 위치 저장
    → 같은 차량의 실제 ON 신호 및 새 유효 차량 위치 확인
    → 같은 정비소인지 확인
    → OFF~ON 경과 시간이 30분 이상이면 체류 조건 충족으로 추정
    → 아래 질문 대상 조건 확인
    → 차량 출차 확인
    → 다음 차량 정차 확인 후 휴대폰 질문 배너
```

30분은 제품의 방문 추정 기준이며 엔진오일 작업 소요시간을 증명하는 값이 아닙니다. 정비소에서 다른 정비를 했거나 중간에 차량이 이동했을 가능성도 있어 추정 기록임을 명시하고 사용자에게 취소 기회를 제공합니다.

정확히 30분이면 충족, 30분 미만이면 미충족입니다. **OFF·ON과 동일 시설을 확인했다면 중간에 SDK/Bluetooth 수신이 끊겨도 경과 시간을 인정**합니다. 이전의 “모든 수신 공백 시간은 체류에서 제외” 제안은 이 경우 적용하지 않습니다.

반대로 연결 끊김만으로 OFF를 만들거나 재연결만으로 ON을 만들지 않습니다. 일반 신호대기 중 자동 시동 정지, HEV의 엔진만 정지, 차량의 실제 전원 종료를 구분할 수 있는지 검증해야 합니다. 실제 전원 의미를 확인하지 못한 엔진 RPM=0·속도=0·P/N은 OFF 대체 증거가 아닙니다.

OFF 또는 ON 증거·위치·시설 연결이 없거나 시각이 역전된 경우 자동 질문의 근거로 인정하지 않습니다. 같은 차량의 실제 사이클로 연결하고 중복 OFF 콜백으로 시작 시각을 계속 덮어쓰지 않습니다. 같은 시설 판정의 위치 정확도·반경·유효시간과 실제 상태 API는 친구가 검증해 확정합니다. 이 문서가 5초 수신·종료 후 상시 수신 등을 보장하지 않습니다.

### 6.2 질문 대상

| 현재 이력 | 추가 조건 |
|---|---|
| 확정 교체 기록 또는 정확한 과거 교체일 있음 | 교체 주기 도달 + 30분 OFF→ON 체류 추정 |
| 대략 교체일 있음 | 가입 전 20km/일과 기간으로 계산한 교체 주기 도달 + 30분 OFF→ON 체류 추정 |
| 마지막 교체일 자체가 없음 | 주기 도달 여부와 무관하게 30분 OFF→ON 체류 추정. 초기 기록 확보용 예외 |

주기가 도달했는지는 출차 후 질문을 준비할 때 최신 유효 계산으로 확인합니다. 대략 날짜 차량에 무조건 방문 질문을 띄우던 안은 폐기합니다. 30분 조건 후에도 차량 출차와 다음 정차를 확인합니다. 휴대폰 소지자의 도보 이동으로 차량 출차·정차를 만들지 않습니다.

## 7. 자동 추정 기록과 취소 — 2026-11-15 사용자 변경

배너: **“엔진오일 교체한 것 같아!”**, 선택: **“교체 안 했어요” / “기록 보기”**. 유효한 방문 조건을 모두 만족하면 먼저 `ENGINE_OIL` / `EstimatedOilVisit` 기록을 저장하고 주기를 재계산합니다.

| 응답·상태 | 결과 |
|---|---|
| 기록 보기 | 이미 적용한 추정 기록을 유지하고 관리기록 화면 열기 |
| 교체 안 했어요 | 추정 기록 취소, 이전 유효 교체 기준 복원, 거절 ID 보존 |
| 무응답·닫기 | 적용한 추정 기록 유지, 같은 방문으로 재기록하지 않음 |
| 오일량 부족→정상, 오일 압력 경고 해제 | 상태 변화만 저장. 교체 기록·100% 초기화의 근거 아님 |

관리기록에서 엔진오일 교체를 직접 추가하는 경로는 유지합니다. 30분 미만 교체, 주기 전 조기 교체, 시동·위치 수신 실패, 지도에 없는 장소의 교체를 이 경로로 반영할 수 있습니다. 다른 정비·타이어·워셔액 기록은 엔진오일 초기화 근거가 아닙니다.

자동 추정 기록의 기본 완료 시각은 해당 방문의 출차 시각, 기준 거리는 출차 무렵에 가장 가까운 유효 차량 누적거리입니다. 이는 작업 순간을 직접 측정한 값이 아니라 확인된 방문의 대표 시각·거리입니다. 수정할 수 있게 합니다.

기준 거리를 받지 못하면 임의 숫자나 며칠 뒤 재연결 거리를 과거 교체 거리로 자동 대입하지 않습니다. 날짜 기록은 저장하고 기간 기준으로 관리하며, 기준 거리 보완 전에는 완전한 종합 잔여율을 표시하지 않습니다. 추정 여부와 거리 기준 확보 여부는 별도입니다. 정상적으로 날짜·거리가 함께 저장되면 100%로 시작합니다.

날짜만 확정된 실제 교체 이후의 거리 미수신을 가입 전 평균 20km 규칙으로 무조건 채우지 않습니다. 가입 전 과거 이력 추정과 이후 실제 기록의 수신 실패는 서로 다른 경우입니다.

## 8. 알림·캐릭터

- 화면·캐릭터·휴대폰 알림은 같은 차량의 동일 주기·계산 결과를 사용합니다. 기존 캐릭터 색상·표정 규칙을 재사용하며 디자인을 새로 바꾸지 않습니다.
- 교체 주기 도달 안내와 정비소 교체 확인 질문은 별개입니다. 주기 도달 안내를 보냈다고 교체 기록이 생기지 않습니다.
- 이력 미등록 차량에는 설치 후 주기 도달 안내를 별도로 사용하며, 잔여율을 만들지 않습니다.
- 같은 교체 주기·같은 알림 단계는 앱 재시작·재연결·재전송만으로 반복 발송하지 않습니다. 새 교체 기록으로 다음 주기를 시작합니다.
- 새 20% 사전 알림 기본값은 확정된 항목이 아닙니다. 기존 사용자 알림 설정과 OS 권한을 존중하고 추가 임계값은 별도 결정 없이 하드코딩하지 않습니다.
- 사용자 확인으로 생성된 엔진오일 교체 기록의 완료 안내는 일반 정비 완료와 구분합니다. 다른 정비를 엔진오일 완료로 바꾸지 않습니다.
- 오일량·압력 안전 신호는 교체주기와 별도입니다. 잔여율이 높다고 실제 차량 경고를 정상으로 치환하지 않습니다.

## 9. 기록·동기화·오프라인

- 휴대폰은 기존 프로젝트의 차량별 설정·관리기록 권한 체계를 따릅니다. 차량은 방문·차량 신호를 수집하고 요청을 전달합니다. 두 앱이 독립적으로 서로 다른 교체 기준을 확정하지 않습니다.
- 안정적인 차량 ID, 방문 ID, 교체 기록 ID를 사용합니다. 차량 선택 화면을 바꿨다고 수신 차량을 다른 차량으로 바꾸지 않습니다.
- OFF 시각·시설 ID·위치·차량 ID·미완료 방문을 저장해 앱 종료·재부팅 후 이어받습니다. 복원 후에도 실제 증거의 유효성을 검사합니다.
- 질문 표시/응답 상태, 기록 버전, 취소·삭제 ID를 저장해 재전송·중복 클릭·역순 수신에서 같은 방문의 기록을 하나만 생성합니다. 초기화는 교체 기록의 저장에 종속시킵니다.
- 날짜가 같다는 이유만으로 다른 기록을 병합하지 않습니다. 같은 방문 질문의 중복 확인은 하나로 처리하지만 같은 날 엔진오일과 타이어 정비는 별도 기록입니다. 자동·수동 기록도 같은 실제 교체로 연결할 근거 없이 날짜만으로 합치지 않습니다.
- 기록 수정·삭제·취소 시 가장 최근의 유효 엔진오일 교체 기록으로 재계산합니다. 기준이 전혀 남지 않으면 이력 미등록으로 돌아갑니다. 보존된 최초 가입 이력 추정이 유효하게 남아 있다면 그 기준을 사용할 수 있으며 사용자가 삭제한 기록을 되살리지 않습니다.
- 주기 변경도 재계산 사유이며 새 교체를 뜻하지 않습니다. 주기 변경으로 퍼센트가 올라가도 교체 완료 기록·배너를 만들지 않습니다.
- Bluetooth 범위 밖에서 실시간 전달을 보장하지 않습니다. 재연결 시 유효 상태와 기록을 동기화하고 과거 방문 질문을 중복 발송하지 않습니다. 이미 끝난 방문에 주행 중 지연 질문을 표시하지 않게 현재 정차를 확인합니다.

## 10. 친구가 검증할 사항 — 정책 변경이 아닌 구현 검증

1. **SDK 의미:** 실제 차량 전원 OFF·ON을 구분해 받을 수 있는가? 엔진 자동 정지·HEV 엔진 정지를 제외할 수 있는가? 미지원이면 이 자동 경로를 생략하고 직접 기록으로 보완합니다.
2. **위치·시설:** OFF와 ON의 차량 위치로 같은 정비소를 연결할 수 있는가? 시설 ID/구역·정확도·관측 시각·경계 오차·출차를 확인합니다. 허용 반경·최신성 수치는 시험 후 정하며 확정값처럼 쓰지 않습니다.
3. **거리:** 수신 단위, 초기값, 동일값, 역전, 수신 공백 복구를 확인합니다. 평균과 실제 거리를 이중 합산하지 않습니다.
4. **생명주기:** 시동 종료·앱 화면 종료·SDK 단절·Bluetooth 단절·앱 프로세스 종료를 구분합니다. OFF 저장 직후 앱 종료, 재부팅 후 ON에도 증거와 질문 상태가 복원되는지 확인합니다.
5. **전달·중복:** 차량→휴대폰 실제 무선, 오프라인 응답, 재전송·중복 클릭·양쪽 편집·취소 복원을 확인합니다. 기존 S24/S7 시험을 Pleos 시동 신호 검증으로 간주하지 않습니다.
6. **판단 흐름:** 주기 미도달/도달/이력 미등록, 29분59초/30분, 같은 시설/다른 시설, OFF만/ON만/연결 단절만을 나눠 검사합니다.

시험 신호·시간 이동·위치 시나리오는 데모/검증 데이터로 분리합니다. 실제 관리 기록을 시험으로 초기화하지 않습니다. 관련 실기기 검사는 [Bluetooth 검증 목록](../BLUETOOTH_VALIDATION_CHECKLIST.md)에 함께 남깁니다.

## 12. 이번 커밋의 범위

새 합의 문서와 기존 문서의 안내·우선순위·실기기 검증 항목만 정리했습니다. 앱 코드·교체주기 JSON/CSV·기존 관리기록·UI·SDK·알림 구현은 변경하지 않습니다. 문서의 새 기준이 실제 앱에 적용됐다고 보고하지 않습니다.

## 구현 증거 제약

Vehicle SDK 2.3.2 자체에서 전원 조회는 검증되지 않았습니다. 별도의 공개 AAOS `IGNITION_STATE`를 기존 Car 연결에서 읽고 정상 권한·지원 여부·원본 시각을 확인합니다. 실제 OFF/ON 콜백, 정확도가 있는 차량 위치, 구분 가능한 정비소 구역, 출차·다음 정차 중 하나라도 없으면 자동 기록하지 않습니다. 30m 위치 정확도·24시간 사이클 상한은 보수적인 구현 시험값이며 실차 확정값이 아닙니다. 현재 환경의 실제 지원 결과는 별도 검증 보고서에 기록합니다.

## 12. 최종 사용자 변경 — 세차와 같은 수신 공백 체류 추정 허용

이 절은 위의 **실제 전원 OFF/ON만 자동 방문으로 인정**하던 제한을 대체한다. 검증된 실제 전원 경로는 유지하고, 다음 조건을 모두 만족하면 전원 API 미지원이어도 별도의 추정 경로를 인정한다.

1. 구분 가능한 지도 정비소 구역 안에서 실제 차량의 신선한 속도0·기어가 있는 정차 위치를 저장한다.
2. 마지막 유효 정차 관측부터 최소30분(최대24시간) 공백 뒤, 같은 시설·20m 이내에서 실제 차량의 신선한 속도0·기어·위치를 다시 받는다. 양쪽 측정/수신 시각 순서와 경과 시간이 일치해야 한다. 원본 시각이 오래된 캐시를 재수신한 것은 인정하지 않는다.
3. 계속 들어오는 정차 관측은 저장 기준을 갱신한다. 따라서 연속 수신 중인30분 주차는 수신 공백이 아니다. 도중에 유효한 이동·구역 이탈이 관측되면 공백 기준을 버린다. 초기 Loading/NoData는 정차 근거로 세지 않으며 구역 안의 마지막 실제 정차 기준은 보존할 수 있다.
4. 해당 정비소 구역에서 실제 차량의 D·이동으로 출차하고, 그 다음 구역 밖 정차를 확인한다. 재연결만으로 출차·교체를 만들지 않는다.
5. 이력 날짜가 있으면 가혹 교체 주기 도달이 필요하다. 날짜 미상만 기존 첫 기록 확보 예외를 유지한다. 유효 방문은 먼저 추정 기록하고 무응답은 유지, “교체 안 했어요”는 취소한다.

세차와 같이 실제 위치 정확도가 미제공이면 미상으로 유지하고 지도 경계의 불확실 구간은 제외한다. 알려진 정확도30m 초과는 제외한다. 20m·30m·24시간 값은 보수적 구현 기준으로, 실차의 정확도나 정비 완료를 보증하는 수치가 아니다.

추정 경로의 증거는 `SAME_PLACE_RECEIVING_GAP`, 기존 전원 경로는 `AAOS_IGNITION_STATE`로 구분한다. 기존 직렬화의 off/on 필드는 각각 공백 전/후 관측을 담을 수 있으나 evidence 없이 OFF/ON이라고 해석하지 않는다. 기록 상세에는 “수신 공백 후 재수신 … 시동 확인 아님”을 표시한다. 이 추정은 실제 시동 종료·연속 체류·엔진오일 작업을 증명하지 않으며, 중간에 이동했다 돌아왔을 가능성이 있어 취소 가능한 추정으로만 사용한다.

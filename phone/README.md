# 베모링 휴대폰 앱

차량 앱의 파란색·네이비·민트 색상과 기존 베모링 캐릭터를 이어받은 Kotlin / Jetpack Compose 휴대폰 UI입니다. `app`과 별도로 설치되는 `phone` Android 모듈입니다.

## 실행

저장소 루트를 Android Studio에서 열고 Gradle Sync 후 실행 모듈을 `phone`으로 선택합니다. 휴대폰 테스트 기기는 Device Manager의 **Vemoring Phone API 34** (`Vemoring_Phone_API_34`, Android 14)를 선택합니다. Pleos 에뮬레이터 설정은 변경하지 않습니다.

휴대폰 AVD는 공식 AOSP API 34 x86_64 이미지와 Medium Phone 프로필을 사용합니다. RAM 2048 MB, CPU 3코어, 해상도 1080×2400, 밀도 420 dpi로 기존 휴대폰 기기와 같은 하드웨어 설정을 유지합니다. 현재 앱은 Google Play 서비스가 필요하지 않아 Google 앱이 없는 기본 이미지로 검증합니다. 추후 Play 서비스가 필요한 기능을 추가하면 해당 기능은 별도 Google APIs/Play 이미지 또는 실기기에서 검증해야 합니다.

`minSdk=28`, `compileSdk=37`, `targetSdk=37`은 유지합니다. Android 공식 문서상 실행 가능한 OS 하한은 `minSdk`로 결정되므로 현재 APK는 API 34에서도 실행 가능합니다. `compileSdk`/`targetSdk`만 낮춰도 에뮬레이터 OS나 PC RAM 할당이 바뀌지는 않습니다. 근거: [AVD 시스템 이미지와 minSdk](https://developer.android.com/studio/run/managing-avds#system-images), [uses-sdk](https://developer.android.com/guide/topics/manifest/uses-sdk-element).

16 GB PC에서는 휴대폰 AVD와 Pleos AVD를 한 번에 하나씩 실행합니다. API 34 전환만으로 메모리 경고가 사라진다고 보장할 수는 없습니다. API 34 실행 검증 후 사용자 요청에 따라 기존 `Medium_Phone_API_37.0` AVD 및 API 37 휴대폰 시스템 이미지를 삭제했습니다. 빌드용 API 37 플랫폼과 차량용 Pleos 이미지·AVD는 유지합니다.

기존 휴대폰 기기의 전체 데이터·설정은 이 PC의 `C:\Users\zlxld\.android\avd-backups\Medium_Phone_API_37.0-20261109`에 백업했습니다. 파일 수·크기를 대조하고 `userdata-qemu.img.qcow2` SHA-256 일치를 확인한 후 원본을 삭제했습니다. 새 API 34 기기는 별도의 저장 공간을 사용하며 기존 기기 데이터는 자동 이전하지 않았습니다. 백업으로 API 37 기기를 복원하려면 삭제한 공식 시스템 이미지부터 다시 설치해야 합니다.

```powershell
.\gradlew.bat :phone:assembleDebug
```

APK: `phone/build/outputs/apk/debug/phone-debug.apk`  
앱 ID: `com.example.vemoring.phone` (차량 앱과 분리)

## 화면과 동작

- 하단 메뉴: 차량 앱과 같은 홈·관리 기록·내 차, 같은 선 아이콘.
- 홈: 로고·날짜·데이터 연결·알림 → 말풍선·캐릭터·차종·차량 번호 → 차량 컨디션 → 종류별 최근 관리 → 내 주변 찾기 순서. 데이터 연결은 별도 탭 대신 상단 안내 창으로 표시합니다.
- 관리 기록: MY CAR LOG·관리 기록·상단 추가 버튼 → 월별 달력·종류별 표시 → 종류 범례 → 최근/전체 기록 목록. 날짜 선택·해제, 최근/전체 보기, 기록 추가·수정, 미래 날짜 추가 방지를 지원합니다.
- 기록을 저장하면 해당 월·날짜로 이동합니다. 입력창에는 키보드 닫기·완료 동작이 있고 키보드가 열려도 저장 버튼을 유지합니다.
- 내 차: MY GARAGE·내 차 설정 → 네이비 파트너 카드 → 차량 정보 → 차량 상태 아이콘 기능 안내 → 관리 알림 → 관리 기준 설정. 휴대폰에서는 상태 아이콘 기능을 실행하지 않고 차량에서 설정하도록 안내합니다.
- 차량 정보 편집은 차량과 같은 제조사·차종 목록 및 직접 입력, 마지막 관리 날짜 편집을 제공합니다. 닉네임 행은 닉네임만 빠르게 변경합니다. 로컬 세차 기록의 청결도·캐릭터 추정은 차량과 공통 공식을 사용합니다.

차량 앱과 화면 구성·정보 순서·제목을 맞추고, 작은 화면에서 카드들을 한 열로 배치합니다. 주변 배너의 폭·높이는 종류를 바꿔도 유지하며 배너를 누르면 설치된 지도 앱 선택 창을 엽니다. 앱을 고르면 현재 카테고리의 검색 결과로 이동하고, 처리할 앱이 없으면 안내를 표시합니다. 관리 알림과 기준은 실제 알림 발송·차량 설정 변경을 수행하지 않습니다.

선택 목록은 설치되어 검색 실행이 가능한 네이버지도·카카오맵으로 한정합니다. Pleos 기본 내비게이션은 차량 전용이며 휴대폰에는 표시하지 않습니다. 한글 입력기 설치와 차량 기능 대조표는 [PHONE_FEATURE_PARITY.md](../docs/PHONE_FEATURE_PARITY.md)를 참고하세요.

차량 프로필의 초기값은 예시입니다. 기록은 빈 상태에서 시작합니다. 프로필·기록은 이 앱의 전용 SharedPreferences에 JSON으로 저장하며 읽기·쓰기는 IO dispatcher에서 수행합니다. 차량에서 블루투스로 받은 데이터는 별도 캐시에 보관하고 기존 휴대폰 기록을 덮어쓰지 않습니다. 앱 재실행 후에도 유지되지만 앱 삭제 또는 데이터 삭제 시 사라집니다.

시스템 다크 모드, 시스템 글자 크기, 스크롤, 시스템 영역 여백을 지원합니다. 외부 폰트, 애니메이션, 폴링, Pleos SDK 의존성을 추가하지 않았습니다.

## 차량 연결

차량→휴대폰 단방향 Bluetooth RFCOMM 연결과 마지막 수신 데이터 저장을 구현했습니다. 차량 앱의 `내 차 → 휴대폰 연결`과 휴대폰의 `홈 → 데이터 연결 → 블루투스 차량 연결`에서 페어링 상대를 각각 선택합니다. 정상 수신·저장된 프로필·기록·컨디션·캐릭터를 반영하고 단절 시 마지막 수신 시각과 함께 유지합니다. 차량 데이터는 휴대폰에서 수정하지 않으며 `휴대폰 기록 보기`로 전환하면 기존 로컬 기록을 편집할 수 있습니다.

실제 Pleos 차량의 RFCOMM 접근 가능 여부와 실물 Bluetooth 양방향 통신 경로는 미검증입니다. 공식 문서상 현재 Pleos 에뮬레이터는 Bluetooth 동글 연동을 지원하지 않습니다. 픽셀 화면 미러링, 계정, 양방향 편집, 푸시 알림은 구현하지 않았습니다. 연결 절차·지원 범위·검증은 [PHONE_COMPANION_SYNC.md](../docs/PHONE_COMPANION_SYNC.md)를 참고하세요.

2026-11-09 공식 [공모전 FAQ](https://appdevchallenge.auto-hmg.io/faq)를 확인했습니다. API 28 이상, Gradle 8 이상, Java/Kotlin 요구사항을 유지하며 기존 저장소의 SDK/Gradle 버전을 그대로 사용했습니다. 휴대폰 인증·연동 방식이 공식 제공된다고 가정하지 않았습니다.

## 검증

2026-11-09 두 앱의 debug APK 빌드, 단위 테스트(차량 29개·공유 프로토콜 4개), Lint를 통과했습니다. API 34 휴대폰에서 격리된 verification 앱의 기기 테스트 3개로 배너 폭·높이 및 큰 글씨, 카테고리 검색 인텐트, 마지막 정상 스냅샷의 실제 디스크 저장·재로드를 확인했습니다. 기본 휴대폰 앱의 로컬 기록은 격리 테스트 전후 대조했습니다.

휴대폰에서 세 종류 배너와 지도 앱 선택 창을, 공식 Pleos 환경에서 차량의 휴대폰 연결 카드·연결 창을 스크린샷으로 확인했습니다. Pleos는 공식 4 GB RAM·해상도를 유지하고 Cold Boot했으며, 두 에뮬레이터를 동시에 실행하지 않았습니다.

실차 Bluetooth 통신과 설치된 실제 지도 앱에서의 최종 검색 결과는 미검증입니다. 최초 기기 테스트의 기본 앱 자동 제거 및 마지막 확인본 복원, 이후 테스트 격리 조치는 [동기화 검증 문서](../docs/PHONE_COMPANION_SYNC.md)에 기록했습니다.
